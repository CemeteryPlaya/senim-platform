Ты ведущий инженер и интегратор проекта **«Сенім»** (репозиторий `mvp-scale-arna`). Цель — довести текущий MVP до качественного продукта, который мы покажем банку (основная цель — Freedom Bank), чтобы получить доступ к эскроу-счетам и их API. ## 2. Продуктовые решения (зафиксированы, не меняй)

- **Продукт:** платформа безопасных сделок на мебель на заказ. Город — Астана. Язык — только русский.
- **Исполнители:** частные мастера (самозанятые, ИП) и компании (ТОО). Регистрация с подтверждением оператором; оператор также может добавить исполнителя вручную.
- **Два входа для заказчика:**
  1. **Тендер:** заказчик заполняет заявку, её видят все подтверждённые исполнители нужного сегмента; они откликаются.
  2. **Прямой запрос:** заказчик находит мастера по похожей работе в портфолио («Хочу похожее») и отправляет заявку только ему.
- **Типы мебели:** вся домашняя мебель. Справочник ведёт оператор, заказчик может вписать свой вариант текстом.
- **Сегменты «Эконом», «Комфорт», «Премиум»** присваивает исполнителю оператор вручную. Заказчику сегмент подсказывается правилами по материалам и размерам, с кнопкой «Почему?».
- **Анонимность:** заказчик не видит название, имя и телефон исполнителя («Исполнитель №17»). Общение — только во внутреннем чате; в сообщениях маскируются телефоны, ссылки на мессенджеры и e-mail. Исполнитель раскрывается **только в договоре**: наименование или ФИО и ИИН/БИН. Телефон не раскрывается нигде.
- **Замер** делает замерщик исполнителя. Условия задаёт исполнитель в профиле и уточняет в отклике: «бесплатно», «включён в стоимость заказа» или «10 000 ₸ за выезд, если сделка не состоялась» (оплата после, напрямую исполнителю). Платформа деньги за замер не принимает.
- **Оплата сейчас без эскроу:** заказчик платит исполнителю напрямую по этапам. Заказчик отмечает «оплатил», исполнитель подтверждает получение, оба подписывают акт этапа. Должен быть шаблон этапов без аванса (есть исполнители, работающие без предоплаты).
- **Эскроу — цель переговоров с банком.** Код должен показать банку готовую точку подключения (раздел 4, модуль `payments`).
- **Подпись:** договор и акты — PDF, подпись ЭЦП через eGov Mobile (QR) или NCALayer. Сейчас мок-провайдер, реальный — за интерфейсом.
- **Вход:** по номеру телефона и SMS-коду. Демо-режим с переключением персон остаётся, но только под флагом `DEMO_MODE=true`.
- **Споры:** сейчас разбирает оператор вручную. Каждый спор и решение сохраняются структурированно — это будущие данные для ИИ.
- **Демо и хостинг:** демо и показ банку — на Vercel с тестовыми данными. Реальные клиенты появятся только после переезда в облако в РК (это делает владелец). Код должен работать в обоих окружениях без переписывания.
- **Дизайн:** по макетам основателей в `docs/design/mockups/` (владелец положит 7 изображений). Стиль может меняться, поэтому все цвета, шрифты, радиусы и отступы — только через дизайн-токены.

## 4. Целевая архитектура

Модульный монолит. Каждый модуль — папка `src/modules/<name>/` с публичным `index.ts`. Импорт из другого модуля — только через его `index.ts` (ESLint `no-restricted-imports`).

```
src/
  app/                    # маршруты и экраны, без бизнес-логики
  modules/
    identity/             # SMS-OTP, сессии, роли, RBAC, регистрация исполнителя
    companies/            # профиль исполнителя, портфолио, сегмент, условия замера, отзывы, анонимизация
    requests/             # заявки (тендер/прямая), отклики, сравнение, выбор, замер
    deal-core/            # сделка, этапы, акты, споры, журнал; НЕ знает про мебель
    payments/             # PaymentRail: manual | escrow-simulator | bank (заглушка)
    documents/            # PDF договора и актов, хэши, SignatureProvider
    files/                # StorageProvider, EXIF, перцептивный хэш, загрузка по подписанной ссылке
    notifications/        # in-app уведомления, SmsProvider, шаблоны
    operator/             # модерация, справочники, споры, отчёты, сверка
    ai/                   # AiProvider, помощник по заявке, визуализация, лимиты и стоимость
    audit/                # неизменяемый журнал событий, общий для всех модулей
  verticals/furniture/    # типы мебели по умолчанию, стили, шаблоны этапов, правила сегмента
  platform/               # db, env (zod), jobs, logger, errors, rate limit
  ui/                     # дизайн-токены и базовые компоненты
  i18n/ru.ts
```

**Ключевые принципы:**
- **`deal-core` переносим в другие проекты:** всё мебельное — в `verticals/furniture`, ядро получает это как конфигурацию.
- **Все внешние сервисы — за интерфейсами с моком и реальной реализацией;** выбор через переменные окружения, проверенные zod в `platform/env.ts`:
  - `SmsProvider`: `mock` (код в логе и в демо-баннере) | `http` (скелет под казахстанского провайдера);
  - `SignatureProvider`: `mock` | `sigex` (по документации SIGEX и открытой библиотеке `sigex-qr-signing-client`; если документация недоступна — только интерфейс и TODO);
  - `StorageProvider`: `local` (dev) | `s3` (любое S3-совместимое, в том числе будущее облако РК) | `vercel-blob` (демо);
  - `AiProvider`: `mock` | реальный провайдер (ключ даёт владелец);
  - `PaymentRail`: `manual` | `escrow-simulator` | `bank` (только интерфейс и документация).
- **`PaymentRail` — главный аргумент для банка.** Операции: `openAccount(deal)`, `getRequisites`, `onDeposit` (вебхук), `releaseTranche(stage)`, `refund`, `getStatement`; идемпотентные ключи и сверка с журналом.
  - `escrow-simulator` — встроенный «банк-симулятор», честно подписанный в интерфейсе как симулятор: эмулирует счёт, вебхуки и выписку, чтобы показать полный цикл эскроу.
  - Статусная машина сделки учитывает режим: в `manual` нет шага пополнения, в эскроу-режимах он есть.
- **Фоновые задачи совместимы с Vercel:** таблица `Job` + защищённый `CRON_SECRET` маршрут `/api/cron/run` + `vercel.json` с расписанием + локальный скрипт `npm run jobs`. Задачи идемпотентны (автоприёмка этапа, напоминания, обработка ИИ-задач).
- **Безопасность:** ИИН шифруется в БД (AES-256-GCM, ключ из env), в интерфейсе — последние 4 цифры; сессия — httpOnly cookie и таблица сессий с отзывом; лимиты частоты на вход и SMS; журнал аудита только на добавление.

## 5. Модель данных и статусы

Реализовано в `prisma/schema.prisma` (фаза A). Статусную машину каждой сущности описать таблицей переходов (`from`, `to`, кто может, условия) в коде и покрыть тестами каждый разрешённый и каждый запрещённый переход.

- Request: `DRAFT → OPEN → OFFER_CHOSEN → MEASURING → CONTRACTING → CLOSED`, а также `CANCELLED`. Черновик сохраняется на каждом шаге мастера.
- Offer: `SENT | WITHDRAWN | DECLINED | ACCEPTED`. На одну заявку — один отклик от исполнителя.
- Measurement: `SCHEDULED | DONE | NO_DEAL | CANCELLED`, начисленная плата за выезд (только запись).
- StagePayment: `DUE → MARKED_PAID → CONFIRMED`.
- Dispute — структурировано: причина, позиции сторон, вложения, решение, обоснование.

## 6. Экраны

Все экраны — по макетам и правилам доступности:
- основной текст ≥ 17–18 px, вторичный текст с контрастом ≥ 4,5:1;
- кнопки и поля ≥ 48 px по высоте, одно главное действие на экране, кнопка «Назад» всегда видна;
- учитывается системное увеличение шрифта, работает с клавиатуры, мобильный экран — основной.

**Заказчик:**
1. Лендинг с выбором роли. В текстах **нет** обещаний «безопасной оплаты/эскроу», пока режим `manual`; формулировки — «оплата по этапам под контролем».
2. Мастер заявки: «Что делаем» (тип) → «Стиль» → «Помещение» (фото или чертёж, ИИ-иллюстрация, кнопка «Пропустить») → «Детали» (разбить на 2 экрана; у каждого технического поля вариант «Не знаю — подскажет исполнитель») → «Сегмент и отправка». Единый степпер на всех экранах.
3. Каталог работ с фильтрами и кнопкой «Хочу похожее» → прямой запрос.
4. «Мои заявки» → список откликов с сортировкой → карточка отклика (одна длинная страница вместо 5 вкладок) → «Выбрать и перейти к замеру».
5. Сделка: договор (просмотр PDF, подпись), этапы, оплата этапа, акты, чат, спор, отзыв.

**Исполнитель:** регистрация (ожидание подтверждения), профиль и портфолио, условия замера, входящие заявки (тендер и прямые), форма отклика, замеры (итоговая цена), сделки, сдача этапа с фото, подтверждение получения оплаты.

**Оператор:** очередь регистраций, ручное добавление исполнителя, сегменты, справочник типов мебели; заявки без откликов дольше N часов, споры, журнал аудита с фильтрами; отчёт и сверка по сделкам и этапам, «Сбросить демо» (только при `DEMO_MODE`), переключатель режима `PaymentRail` для демо.

**Показ банку:** страница-сценарий (только при `DEMO_MODE`), которая проводит по полному циклу и показывает журнал, документы с хэшами и режим `escrow-simulator`.
