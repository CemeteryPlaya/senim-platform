Дата: 02.11.2026 (фазы A–F — 31.10.2026, фаза G — ответы владельца и встреча 31.10). Задание — `docs/AGENT_PROMPT.md`. Ход работ и журнал решений — `docs/PROGRESS.md`. Ветка `main`, ничего не отправлено в удалённый репозиторий и не развёрнуто.

## Итог

MVP пересобран в модульный монолит на Next.js 16, Prisma 7 и PostgreSQL. Полный путь продукта работает на демо-данных: заявка → отклики → замер → договор с ЭЦП (мок) → этапы с актами и оплатой → спор → завершение и отзыв. Эскроу показывается встроенным симулятором банка; реальный банк подключается через интерфейс `PaymentRail` без изменения остального кода. Все внешние сервисы — на моках за интерфейсами, по решению владельца.

## Что сделано по фазам

**A — фундамент.** Гигиена репозитория; Docker Postgres (порт 5442); vitest (unit + integration на отдельной БД), Playwright, CI-проверка; модули и ESLint-границы; `platform/` (env на zod, db, ошибки, логгер с маскировкой, шифрование ИИН AES-256-GCM + HMAC, фоновые задачи, rate limit, `action()`); журнал аудита с триггером append-only; схема данных и миграции; контракты провайдеров с моками; вертикаль «мебель»; дизайн-токены по 7 макетам, базовые компоненты и оболочка; сид демо-данных; ADR-001…003, глоссарий, правила для агентов.

**B — 8 модулей параллельно.** identity (SMS-вход, сессии, роли, демо-персоны, регистрация исполнителя), requests (мастер заявки, отклики, замер), companies (профиль, портфолио, каталог, чат с маской контактов), deal-core и payments (статусные машины, этапы, оплаты, споры, автоприёмка, симулятор эскроу, вебхуки, сверка), documents (PDF договора и актов с кириллицей, sha256, подпись с проверкой на сервере, скелет SIGEX), files и notifications (хранилища local/s3/Blob, загрузка по подписанной ссылке, EXIF, перцептивный хэш, уведомления, SMS-шаблоны), operator (модерация, справочники, споры, журнал, отчёт и сверка, сброс демо, `/bank-demo`), ai (помощник «опишите своими словами», ИИ-иллюстрация, учёт стоимости). Харнесс выдал всем агентам один общий worktree — ветка получилась линейной.

**C — интеграция.** Связи модулей (SMS по важным событиям, закрытие заявки при подписи договора, одно правило видимости заявки, фото через files), общие файлы (один исполнитель на ИИН/БИН, общие помощники платформы, шапка с колокольчиком и «Выйти»), договоры и акты в сиде, починка запуска dev-сервера в worktree, `npm run jobs` и сида.

**D — проверка.** Четыре круга ревью кода, безопасности и доступности и 11 e2e-сценариев (полный путь, гонки двойного нажатия, доступ к чужим данным).

| Безопасность | 1 / 6 | 0 / 6 | 0 / 4 | (вместе с кодом) |

Все критичные и важные исправлены; находки четвёртого круга исправлены и проверены тестами и e2e (пятого круга ревью не было). Главное из исправленного:
- анонимность исполнителя до договора: маска контактов и ФИО во всех его текстах для заказчика (отклик, замер, отчёт этапа, спор, чат), в том числе обходы невидимыми символами, надстрочными цифрами, кириллическими двойниками; размеры «900*600*2400» не маскируются;
- подпись договора: сверка полного ИИН сертификата по HMAC; ФИО и ИИН заказчика спрашиваются один раз перед договором; подписант исполнителя (директор ТОО, владелец ИП) хранится в профиле; договор ТОО называет директора;
- сделка и деньги: нельзя подписать договор отменённой сделки; заявка закрывается при отмене; спор привязан к нужному этапу; автоприёмка возобновляется после спора; остаток эскроу учитывает операции в пути; зависшие операции досылаются, отклонённые повторяет оператор только когда операция ещё нужна;
- безопасность: открытый редирект закрыт; демо-стенд под паролем; заголовки (запрет встраивания, HSTS, nosniff); моки SMS и подписи запрещены в production; лимиты SMS не дают закрыть вход всем; логи и журнал задач без персональных данных; бюджет ИИ резервируется до вызова;
- доступность: нет обрезания при шрифте 200 % на телефоне; необратимые действия — через подтверждение, двойное нажатие его не обходит; «Назад» везде; фокус на ошибки и после действий; русские 404 и страница ошибки.

**E — материалы для банка** (`docs/bank/`): `01-overview.md`, `02-architecture.md` (Mermaid), `03-escrow-integration.md` (операции, идемпотентность, подпись вебхуков, статусы, сбои, диаграммы последовательности, вопросы к банку; без утверждений об API Freedom Bank), `04-security-and-data.md`, `05-demo-script.md` (показ на 10 минут), `openapi.yaml` (наши вебхуки); обновлён `README.md`. ## Что важно знать

- `prisma migrate reset` от имени ИИ-агента Prisma не выполняет без вашего подтверждения; демо-база пересоздаётся `DEMO_MODE=true npx prisma db seed` (так же работает кнопка «Сбросить демо»).
- Дважды за работу удаление временного worktree опустошало общие пакеты в `node_modules` (git шёл по ссылкам `.next/node_modules`). Пакеты восстановлены по lock-файлу, `sharp` и `pg` загружаются; в дереве остались 6 необязательных WASM-пакетов, которые `npm prune` не убирает. Для полной чистоты — `npm ci`.
- В основном каталоге `git status` показывает изменёнными ~70 файлов `.claude/skills` — это переводы строк (CRLF в репозитории при `core.autocrlf=true`), содержимое не менялось.
- Старые профили ТОО без подписанта (до миграции `executor_signer`) не подпишут договор, пока не обновят анкету; демо-данные перезаполнены.
