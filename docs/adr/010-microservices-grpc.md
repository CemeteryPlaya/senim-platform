# ADR-010: Go-микросервисы, gRPC и отдельный репозиторий v2

Статус: принято (спека утверждена 08.11.2026).

## Контекст

Модульный монолит на Next.js (v1; ADR-009 фиксирует продуктовые инварианты) нужно подготовить к росту нагрузки и числа команд, изолировать данные и права по сервисам и закрыть замечания ревью безопасности от 07.11.2026. Продуктовые инварианты (деньги, статусы, тексты) не меняются.

## Решение

Спека: `docs/superpowers/specs/2026-11-08-platform-v2-architecture-design.md` (разделы 4, 9, 12).

- Сервисы на Go (identity, deal, marketplace, operator, documents, files, notify, audit); `web` (Next.js) остаётся интерфейсом и BFF.
- Синхронно — gRPC (connect-go v2, протокол gRPC поверх HTTP/2, mTLS) через отдельный Envoy mesh-gateway, который балансирует по запросам; на входе — edge Envoy.
- Асинхронно — NATS JetStream; outbox в транзакции изменения, inbox у получателя; изменяющие методы принимают `idempotency_key`.
- Своя база и свои роли PostgreSQL у каждого сервиса; сервис-владелец сам проверяет права по внутреннему токену Ed25519 (5 мин) от `identity`.
- Монорепозиторий `senim-platform`: Go-модуль в корне, `apps/web` импортирован с историей через `git subtree`; Go + pgx + sqlc + goose; локально docker compose (профили `core` и `full`), в проде Kubernetes.
- Переход без синхронизации данных: чистая база, e2e зелёные в двух контрольных точках.

## Последствия

- Плюс: изоляция данных и прав, независимое масштабирование, единые контракты (protobuf) для Go и TypeScript.
- Минус: распределённые сценарии вместо одной транзакции (раздел 4.3 спеки): повторы с `idempotency_key`, outbox/inbox, синхронные вызовы `deal` для подписей оферты и акта.
- Минус: больше инфраструктуры (Envoy, NATS, MinIO, наблюдаемость); бюджет памяти: `core` ≤ 3 ГБ, `full` ≤ 6 ГБ, Go-сервис в простое ≤ 64 МБ.
- `apps/web` расходится с `main` демо; обновления подтягиваются `git subtree pull` часто и малыми порциями.
- Решения, оставленные на проверку владельцу, — раздел 12 спеки.
