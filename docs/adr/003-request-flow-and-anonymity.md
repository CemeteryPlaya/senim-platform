# ADR-003. Путь заявки, чат и анонимность исполнителя

**Статус:** принято (фаза A). Детали — `marketplace-engineer` и `companies-engineer`.

## Заявка
```
DRAFT ──(мастер заполнен, «Отправить»)──► OPEN
OPEN ──(заказчик выбрал отклик)──► OFFER_CHOSEN   (отклик ACCEPTED, остальные DECLINED)
OFFER_CHOSEN ──(замер назначен)──► MEASURING
MEASURING ──(замер DONE, заказчик согласен с итоговой ценой и шаблоном этапов → deal-core.createDeal)──► CONTRACTING
MEASURING ──(замер NO_DEAL)──► OPEN   (отклик DECLINED; плата за выезд — только запись feeAccrued)
CONTRACTING ──(договор подписан обеими сторонами)──► CLOSED
DRAFT | OPEN | OFFER_CHOSEN | MEASURING ──(заказчик отменил)──► CANCELLED
CONTRACTING | CLOSED ──(сделка отменена до начала работ, SYSTEM)──► CANCELLED   (CLOSED — эскроу, отмена в AWAITING_DEPOSIT; ADR-002)
```
- Черновик сохраняется на каждом шаге мастера (`wizardStep`, `details`).
- `TENDER` видят подтверждённые (`APPROVED`) исполнители с тем же сегментом, что у заявки. `DIRECT` видит только `targetExecutorId`.
- Адрес заказчика раскрывается исполнителю только после выбора его отклика.
- Отклик: один на пару «заявка — исполнитель» (уникальный индекс), отзывается исполнителем (`WITHDRAWN`) до выбора.

## Чат
Сообщения привязаны к отклику (`Message.offerId`): чат начинается с отклика и продолжается в сделке. Перед сохранением текст проходит `maskContacts` (телефоны, e-mail, ссылки и упоминания мессенджеров); исходный текст не хранится, `wasMasked` фиксирует факт. Чат ведёт модуль `companies` (слой анонимизации).

## Анонимность
- Заказчик видит исполнителя только через `publicExecutorView`: «Исполнитель №N», сегмент, рейтинг, опыт, условия замера, портфолио. Без наименования, ФИО и телефона. *Уточнено ADR-006:* в режиме «имя показано», который включает оператор, — наименование и полный адрес; телефон по-прежнему нигде.
- Наименование/ФИО и ИИН/БИН раскрываются только в PDF договора (модуль `documents` расшифровывает `binIinEnc` в момент генерации).
- Телефон исполнителя не раскрывается нигде.

## Уточнения при реализации (фаза C)
- Правило видимости заявки исполнителю — одно: `requests/visibility.ts` (`visibleToExecutor` для запросов, `executorSeesRequest` для загруженной заявки; второй использует files для прав на фото помещения).
- «Хочу похожее» доступно только для работы, видимой в каталоге: опубликована, исполнитель подтверждён и не заблокирован.
- Один профиль исполнителя на ИИН/БИН: `ExecutorProfile.binIinHash` (HMAC) с уникальным индексом.
- Файлы отдаются по подписанной ссылке без сессии (как подписанные ссылки S3 и Blob): право доступа проверяется при выдаче ссылки (`files.canReadFile`), а не при скачивании. Иначе гость не увидел бы портфолио. Это осознанное исключение из правила «`requireUser` первой строкой».

## Уточнения фазы D: подписант договора от исполнителя
- **Подписант — свойство профиля исполнителя, а не аккаунта.** `ExecutorProfile.signerFullName`, `signerIinEnc`, `signerIinHash` (HMAC, **без** уникального индекса):
  - ТОО — директор (представитель): ФИО и ИИН обязательны в анкете и при добавлении оператором;
  - ИП — владелец: ФИО владельца спрашивается в анкете отдельным полем, ИИН — ИИН профиля (`binIin*`). ФИО не извлекается из наименования: наименование ИП бывает фирменным («ИП «Дала»»);
  - самозанятый — он сам: наименование профиля и есть ФИО (проверяется как ФИО), ИИН — ИИН профиля.
  Правило одно — `identity.refineSigner`/`signerOf` — для анкеты и для оператора.
- **Почему не `User.iin*`.** Уникальный ИИН аккаунта означал «один ИИН — один аккаунт» и для подписанта: директор двух ТОО не мог зарегистрировать второе, владелец ИП с аккаунтом заказчика не становился исполнителем, опечатка навсегда занимала чужой ИИН, а анкета позволяла занять чужой ИИН и узнать по ответу «ИИН занят», что у человека есть аккаунт. Теперь `registerExecutor` и `addExecutor` не пишут в `User.fullName`/`iin*` и не отвечают «ИИН занят» про подписанта. `User.iin*` — только ИИН заказчика (сторона договора, `recordPersonIdentity` перед договором; один ИИН — один аккаунт заказчика, перебор ограничен до транзакции).
- **Чужой ИИН в анкете безвреден для владельца ИИН.** Подписант профиля не занимает ИИН: настоящий владелец указывает его перед своим договором как обычно. Подписать договор исполнителя чужим ИИН нельзя — нужен сертификат ЭЦП с этим ИИН.
- **Повторная анкета после отказа** перезаписывает подписанта профиля целиком (смена директора, смена ТОО на ИП стирает ИИН директора).
- **Договор ТОО** — «<наименование>, БИН …, в лице директора <ФИО>, действующего на основании Устава» (`signerFullName`). ИП и самозанятый — без «в лице».
- **Маска имени в публичных текстах** (`companies.sanitizePublicText`): наименование целиком (`maskIdentity`) и по отдельности слова ФИО подписанта профиля и владельца аккаунта (`maskNameWords`). Профиль без подписанта (до миграции) у ИП и самозанятого — наименование без «ИП» и кавычек.
