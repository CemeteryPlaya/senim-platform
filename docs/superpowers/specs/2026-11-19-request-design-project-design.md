# Свой дизайн-проект в заявке (v2)

Дата: 19.11.2026. Одобрено владельцем в чате: «А. Видит в заявке, Б. Да» и «план дизайн проекта в заказе тоже утверждаю».

## Зачем

Основатели предложили, чтобы покупатель мог приложить к заказу свой дизайн-проект: план в PDF или фото. Покупатель с готовым проектом получает от мастера точную цену, и мастеру не нужно угадывать по фото комнаты.

## Цели

1. На шаге «Помещение» мастера заявки (`v2/requests/new`, экран `room`) есть блок «Свой дизайн-проект» (необязательный):
   - до 5 файлов;
   - фото (JPEG, PNG, WebP, HEIC) или PDF;
   - фото до 25 МБ, PDF до 20 МБ.
2. Если файлы приложены, обязательна отметка «Я убрал из файлов телефоны, адреса и имена». Без неё шаг не сохраняется: сервер проверяет это сам, экрана для этого недостаточно.
3. Кто видит файлы:
   - мастер — сразу во входящей заявке, то есть ещё до оферты, как фото помещения;
   - покупатель — в карточке заявки;
   - обе стороны — в карточке сделки.

   Ссылки защищённые, живут 15 минут.
4. Оператор может скрыть файл и вернуть его. Каждое действие пишется в аудит в той же транзакции. Скрытый файл не видят мастера и сделка; покупатель видит его с пометкой «Скрыт оператором».

## Не цели

- Распознавать контакты в PDF и на фото. Нельзя замаскировать надёжно, поэтому за это отвечает отметка покупателя, а страховка — скрытие оператором.
- Отдельный шаг мастера заявки: блок встраивается в шаг «Помещение».
- Уведомлять покупателя о скрытии файла.
- Визуализация ИИ по дизайн-проекту.
- Изменения в правилах сценария до договора: онлайн-замер за флагом `preContractFlows` по-прежнему требует фото помещения.

## Решения владельца

- **А.** Мастер видит проект прямо во входящей заявке.
- **Б.** Покупатель подтверждает отметкой, что убрал из файлов контакты.

## Решения исполнителя спеки

1. **Новое назначение файла `REQUEST_DESIGN`** в enum `FilePurpose` (миграция SQL руками: `ALTER TYPE "FilePurpose" ADD VALUE 'REQUEST_DESIGN'`). Политика:
   - загружает только `CLIENT`;
   - `accepts: "imageOrPdf"`;
   - `maxBytes`: 20 МБ (`PDF_MAX`);
   - владелец `requestId`, как у фото помещения;
   - `shortLink: true` — в файле могут остаться контакты, пересланная ссылка должна быстро умирать.
2. **Фото помещения необязательны и сейчас** (путь ТЗ). Поэтому «фото необязательны, если приложен проект» уже выполнено, менять ничего не нужно.
3. **Подтверждение отметки** хранится в `Request.designConfirmedAt TIMESTAMP(3) NULL`:
   - ставится при сохранении шага с файлами;
   - сбрасывается, когда файлов не осталось;
   - отправка заявки (`submitRequest`) ещё раз проверяет: есть файлы `REQUEST_DESIGN` — отметка есть.
4. **Скрытие** — поля `StoredFile.hiddenAt TIMESTAMP(3) NULL` и `hiddenById TEXT NULL`, без внешнего ключа. Скрываем без удаления: покупатель видит свой файл, оператор может вернуть.
   - Право чтения `decideFileAccess`: скрытый файл читают только оператор и тот, кто его загрузил.
   - Ссылку, выданную до скрытия, не отзываем: она умирает за 15 минут.
5. **Где оператор скрывает.** Новая страница `/v2/operator/requests/[number]` «Файлы заявки»: номер заявки и дизайн-проект с кнопками «Скрыть» и «Вернуть». Как оператор туда попадает:
   - форма «Открыть заявку №…» на странице «Заявки без откликов» (`/v2/operator/requests`);
   - ссылка «Файлы заявки» в карточке сделки оператора (`/v2/operator/deals/[id]`).
6. **Действие модуля `setRequestFileHidden`**:
   - запрос — условный `updateMany` по `hiddenAt` (null или не null);
   - повтор не даёт второго эффекта и второй записи аудита;
   - события аудита — `request.design_file_hidden` и `request.design_file_restored`.
7. **Как файлы выглядят на экранах.**
   - Фото — в галерее, как фото помещения.
   - PDF — строкой со ссылкой «Дизайн-проект, файл N (PDF)», открывается в новой вкладке. Имя файла для скачивания — `design-N.pdf`, исходное имя файла не храним.
8. **Мастер заявки:**
   - `designFileIds` и `designContactsConfirmed` входят в шаг `room` (`requests/schema.ts`);
   - `linkRoomPhotos` передаёт `purpose: "REQUEST_ROOM"` в `attachFiles`. Без этого `attachFiles` по полю `requestId` взял бы оба назначения;
   - файлы проекта привязывает новая `linkDesignFiles` с `purpose: "REQUEST_DESIGN"`.

## Ограничения

- Контакты обеих сторон скрыты до оферты: защищаем отметкой покупателя и скрытием оператором. Текст заявки по-прежнему маскируется.
- Тексты только из `ru`, компоненты только из `@/kit`, поля и кнопки ≥ 48 px, одно главное действие на экране.
- Каждое действие: zod и `requireUser` первой строкой. Изменение заявки — в `transaction()` с `recordAudit()`.
- Деньги не затрагиваются.

## Готово, когда

- Покупатель прикладывает PDF и фото проекта. Без отметки шаг не сохраняется, ошибка показывается у отметки.
- Мастер сегмента видит проект во входящей заявке до отклика, обе стороны видят его в сделке.
- Оператор скрывает файл. Мастер его больше не видит, а прямой запрос файла мастером получает отказ (`canReadFile`). Покупатель видит пометку.
- Есть e2e-сценарий v2 на весь путь.
