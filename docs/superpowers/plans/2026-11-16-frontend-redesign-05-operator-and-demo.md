# Новый интерфейс, этап 5 «Оператор и удаление демо» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** (1) демо-режима нет ни как возможности, ни как переменной — в web, `identity`, договоре и документах; стенд и e2e работают через сид из терминала, обычный вход по коду и 2FA операторов без исключений; (2) оператор работает в новом интерфейсе под `/v2/operator` — все разделы v1, 2FA, настройки.

**Architecture:** группа P снимает демо-режим сверху донизу (identity → web → e2e → документы), заменяя его тем, что нужно стенду: сид и сброс стенда только вне `APP_ENV=prod`, метка «засеян сидом», TOTP оператора из сида, пароль стенда без слова «демо». Группа Q строит экраны оператора v2 на `@/kit` над существующими модулями (`src/modules/operator`, `identity`, `payments`, `deal-core`): оболочка с меню слева на компьютере и «Меню» шторкой на телефоне, очереди, сделки, отчёты, справочники, настройки, 2FA с протоколом свежего кода в формах.

**Tech Stack:** Go (connect-go, sqlc, goose, buf) для `identity`; Next.js 16.4.3, React 19, Prisma 7, Tailwind 4, `@/kit`; vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-12-frontend-redesign-design.md` — раздел 9 (демо-режим убирается полностью — что удаляется и решения автора), раздел 5 (оператор: меню слева, «Меню» шторкой на телефоне), раздел 7 (экраны оператора), раздел 10 (этап 5), разделы 14–18 (уточнения и вид). Карта оператора v1 и инвентарь демо — в `constraints.md` рабочей папки.

## Global Constraints

- Пути — от корня репозитория. Ветка `frontend-v2`, без worktree, без пуша; коммит только своих файлов по явным путям.
- Go: `go vet`, `go tool golangci-lint run ./...`, `go tool buf lint`, `go tool buf breaking` (удалённые поля/RPC — `reserved`), `go test ./...` — без ошибок; Go вне PATH: `export PATH="/c/Program Files/Go/bin:$HOME/go/bin:$PATH"`; тесты без `-race`. Сгенерированное (`gen/go`, `apps/web/src/gen`, sqlc) — только генераторами.
- Проверки безопасности при старте не ослабляются: `APP_ENV=prod` по-прежнему запрещает моки SMS, подписи, платежей, почты и провайдер `freedompay`; сид, сброс стенда, мок-коды на экране и пароль стенда — только вне `prod`; сервис с неверной конфигурацией не стартует и называет переменную.
- Продуктовые инварианты `CLAUDE.md` — без изменений, кроме строки о демо (правится по разделу 9 спеки вместе с кодом).
- Экраны оператора v2: компоненты только из `@/kit`, тексты из `ru.app.*`, адреса через `to()`, server actions — zod → `requireUser("OPERATOR")` первой строкой → модуль; действия с деньгами и решение спора — со свежим вторым фактором (`requireRecentMfa`) и протоколом кода в форме; две версии по устройству; сторожа kit/features.
- v1 оператора остаётся рабочим, пока жив v1 (удаление — этап 6), кроме удаления демо-страниц. Экраны v1 не дорабатываются, кроме переноса настроек из `/operator/demo` и снятия демо-веток.
- Базы — только `senim_v2web_test` и `senim_v2web_e2e` на 5442; базы стенда identity — через `npm run v2:*`/`docker compose` по `deploy/compose`. Хуки запрещают пути с «точка + env» и чтение `.pem`/`.key`.
- Проверки в задаче — точечные; полный check, пересев, e2e — автор. Не больше четырёх агентов.

## Решения автора (Ruling, до запуска)

- **R1 пароль стенда:** basic-auth стенда остаётся, переменная `STAND_ACCESS_PASSWORD` (без слова «демо»), действует только при `APP_ENV` не `prod`; при `prod` переменная запрещена. `CRON_SECRET` обязателен, когда задан пароль стенда. Цена: ещё одна переменная стенда.
- **R2 метка сида в identity:** `users.is_demo` переименовывается в `users.seeded` (защита: сид перезаписывает только засеянных людей); `consents.is_demo`/`consent_revocations.is_demo` — в `seeded` с той же логикой триггеров, нужной для сброса стенда. В proto — `User.seeded` (поле `is_demo` → `reserved`). Цена: метка остаётся, но это не демо-функция.
- **R3 сброс стенда:** RPC `ResetDemo` заменяется на `ResetStand` — тот же объём очистки (сессии, коды, лимиты, TOTP засеянных, согласия засеянных, идемпотентность), разрешён только при `APP_ENV` не `prod` и только вызывающему `web`; из интерфейса не вызывается — только сид из терминала. `StartDemoSession` удаляется.
- **R4 TOTP оператора стенда:** `SeedUsers` принимает необязательный секрет TOTP для операторов (только вне `prod`); сид web выдаёт засеянным операторам известный секрет (из `src/<сид>/data.ts`), e2e вычисляет код по `e2e/totp.ts`.
- **R5 код на экране:** `identity` возвращает код входа для показа, когда провайдер SMS — мок (как уже для почты), без условия демо; мок при `APP_ENV=prod` запрещён конфигом (проверить, что это так, и закрыть тестом).
- **R6 `isDemo` в web:** колонки `User.isDemo`, `Deal.isDemo`, `MaterialPrice.isDemo`, `TypicalEstimate.isDemo` удаляются миграцией; `isTest` журнала денег = только провайдер-мок; пометка тестовой операции не показывается покупателю и мастеру (только оператору); пункты «Тестовая сделка» удаляются из договора, акта и выписки целиком.
- **R7 настройки:** режим показа имени исполнителя (ADR-006) и поток до договора переезжают в `/operator/settings` (v1 сейчас, v2 — в Q5); доступ — роль оператора со свежим вторым фактором; условие `DEMO_MODE` снимается.
- **R8 папка сида:** `apps/web/src/demo` → `apps/web/src/seed` (сид стенда), `docs/agents/DEMO_DATA.md` → `docs/agents/STAND_DATA.md`.

## Review Focus

1. Безопасность старта: при `APP_ENV=prod` сервис не стартует с моками, паролем стенда, сидом; при `dev`/`staging` стартует; тесты на каждую ветку (Go и web).
2. Сид не портит настоящих людей: повторный сид перезаписывает только засеянных; сброс стенда — только засеянных; оба отказывают в `prod`.
3. 2FA оператора без исключений: вход засеянного оператора требует TOTP; подтверждение денег и решение спора требуют свежего кода; протокол кода в формах v2 работает.
4. Документы тестовой сделки совпадают с боевыми (договор, акт, выписка); покупатель и мастер не видят пометку «тестовая».
5. Оператор v2: права (только OPERATOR), очередь решений не теряет фокус и не даёт двойного решения, деньги — тиыны через `Money`, таблицы доступны с клавиатуры и при узком окне компьютера.
