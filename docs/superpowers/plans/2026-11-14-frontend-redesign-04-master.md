# Новый интерфейс, этап 4 «Мастер» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** мастер проходит в новом интерфейсе под `/v2` весь путь ТЗ без возврата в старый: регистрация и проверка → входящие заявки → предложение и торг → оферта → работа → сдача с фото и геолокацией → акт → оплата; плюс компания, документы, счёт для оплаты, портфолио, финансы, чаты, уведомления, профиль, помощь.

**Architecture:** экраны, общие для покупателя и мастера (сделка, подпись, спор, история денег, чаты, список сделок), перестают быть «экранами покупателя»: ворота и view-модели получают сторону сделки (`CLIENT` / `EXECUTOR`) параметром, тексты стороны лежат в своих зонах словаря. Экраны только мастера строятся в `src/app/(app)/v2/executor/` и `v2/register/executor/` на тех же модулях `src/modules/*` через свои server actions. Чистая логика мастера из частей v1 (месяцы финансов, сводка входящих, тексты сдачи и геолокации) переезжает в `src/features/`.

**Tech Stack:** Next.js 16.4.3, React 19, Tailwind 4, `@/kit`; vitest, Playwright (`e2e-v2/`, проект `flows` с пересевом).

**Spec:** `docs/superpowers/specs/2026-11-12-frontend-redesign-design.md` — разделы 4–7, 10–12, уточнения в разделах 14–16. Правила вида: `docs/design/v3/rules.md`, `checklist.md`, `components.md`.

## Global Constraints

- Пути — от `apps/web/`, если не сказано иное. Ветка `frontend-v2`, без worktree, без `git stash`, без пуша. Коммит только своих файлов по явным путям (`git commit -- <пути>` или `git diff --cached --stat` перед коммитом).
- v1 (`src/app/(legacy)`, `src/ui`) заморожен: поведение не менять. Разрешено механически заменить путь импорта, когда чистая логика переезжает в `src/features/`. Сигнатуры экспортов модулей не менять; новое — добавлять рядом.
- Экраны v2: компоненты только из `@/kit`; тексты только из `ru.app` (зона мастера — `src/i18n/ru/app/master.ts` и при необходимости `master-*.ts`; общие для обеих сторон тексты — в общих зонах, тексты стороны — в зоне стороны); адреса только через `to()`; версии — только `desktop:` / `mobile:`; server actions — рядом с экраном, через `action()`: zod-схема → `requireUser(<роли>)` первой строкой → модуль. Формы — `useActionForm` + `onSubmit`. Сторожа `src/kit/guards.test.ts` и `src/features/guards.test.ts` обязательны.
- Экран: один `<h1>`, не больше одного `data-primary-action`, «Назад» с названием родителя на вложенных, первая карточка — «Сейчас / Дальше». Телефон: главное действие в `ActionDock`; компьютер: `Split` / `Narrow`.
- Слова для мастера: «покупатель» (не «заказчик», не «клиент» — кроме формулы «Гарантия оплаты и клиента (4%)»), «заявка», «предложение» (не «отклик»), «сделка», «оферта», «сервис» (не «платформа»); нет слов «комиссия», «эскроу», «демо», «тестовый». Мастер видит «Гарантия оплаты и клиента (4%)» и «Вы получите»; нигде не сказано, что деньги проходят через счета сервиса. Покупателю слова мастера не показываются: тест запретных слов покупателя (`buyer-words.test.ts`) остаётся строгим для зон покупателя, у зоны мастера — свой тест.
- Деньги: тиыны, целые; показ через `Money`; формулы — только `computeDealMoney` / `partyEstimate("EXECUTOR", X)` (X − гарантия 4%, вниз до тиына); ничего не считать на экране (исключение — живой расчёт «Вы получите» в форме предложения: только через клиентскую часть модуля `@/modules/payments/client`, как в v1). Блок денег и история — из журнала. Мастеру на экранах не показывается сумма защиты сделки покупателя (2%) и сумма «к оплате» покупателя — симметрично решению этапа 3.
- Имя и контакты покупателя до оферты скрыты так же, как имя и контакты мастера: только то, что отдаёт модуль.
- ИИН/БИН и IBAN — только последние 4 символа; полные значения не попадают в HTML, RSC-пейлоад, журнал и URL.
- Проверку «мастер одобрен» делает модуль (`notApproved`); экраны заявок, сделок и финансов мастера показывают неодобренному мастеру понятный экран статуса, а не ошибку.
- Демо в v2 не переносится. Возможности за флагами (`preContractFlows` — замер, залог, проект; `dealPortfolio`; `clientPhoneConsent`; `executorHandSignsAct`) не переносятся — этап 6; при включённом флаге блока в v2 нет.
- Без `any`, без `console.log`. Хуки запрещают пути и команды с подстрокой «точка + env» и чтение `.pem` / `.key`.
- Базы: только `senim_v2web_test` и `senim_v2web_e2e` на `localhost:5442`; базы `senim`, `senim_test`, `senim_e2e` не трогать даже чтением.

## Harness

Как на этапах 2–3: бриф → исполнитель (модель в заголовке задачи) → точечные проверки и снимки → ревью кода и вида → до трёх кругов правок → журнал. Решения по ходу — строками `Ruling`.

## Review Focus

1. **Две роли у одного человека:** покупатель и мастер в одном лице открывает сделку, чат, уведомление «не в той» роли — понятное переключение или экран своей стороны, без 404 и без петель; свои сделки в обеих ролях не смешиваются в списках.
2. **Неодобренный мастер** (нет профиля, PENDING, REJECTED) на любом экране мастера — экран статуса с понятным следующим шагом; модуль отвечает `notApproved` — экран не падает.
3. **Сдача работы без геолокации или далеко от адреса:** отказ в доступе к геолокации, таймаут, нет https, точка в 5 км — сдача возможна, предупреждение честное, фото обязательны; двойное нажатие — одна сдача.
4. **Деньги мастера:** «Вы получите» в форме предложения и в сделке равно `partyEstimate("EXECUTOR")` до тиына; мастер не видит 2% покупателя; смена счёта запрещена, пока оплата мастеру в обработке — экран объясняет.
5. **Чувствительные данные:** ИИН/БИН, IBAN, документы проверки — нет полных значений в HTML и журнале; чужие документы недоступны; повторная отправка документов и анкеты — один эффект.

## Группа J. Основа экранов мастера

### Task J1: стороны сделки в оболочке и общих view-моделях (Opus 5.5)

**Files:** `_shell/{auth.ts,nav.ts,paths.ts}`, `v2/_parts/*`, `v2/deals/[id]/_parts/gate.ts`, `src/i18n/ru/app/master.ts` + тест слов, тесты.

- Общие view-модели сделки принимают сторону: чип статуса, «Сейчас / Дальше», строка денег, история («Вы» — по стороне), тексты отмены. Таблица «что сейчас» мастера — все значения `next.action` (подписать оферту с согласием банку, ждать подпись покупателя, ждать оплату, начать работу, сдать работу, подписать акт, ждать покупателя, ждать оплату от банка, спор, завершена, отменена, возвращена) с тестом на каждую строку; строки покупателя не меняются (их тесты остаются зелёными).
