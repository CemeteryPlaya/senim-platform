# Новый интерфейс, этап 3 «Покупатель» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** покупатель проходит в новом интерфейсе под `/v2` весь путь ТЗ без возврата в старый: главная → заявка → предложения и торг → оферта → оплата → ход работ → приёмка → отзыв; плюс чат, уведомления, профиль, «Мои данные», «Помощь» и ручной выбор темы.

**Architecture:** экраны v2 вызывают существующие модули `src/modules/*` (домен и статусная машина не меняются) через свои server actions рядом с экранами — действия из `(legacy)` не импортируются. Чистая логика, которая сегодня лежит в частях v1 и в `src/ui` (панель денег, шкала хода сделки, автоматы загрузки и подписи), переезжает в нейтральную папку `src/features/<имя>/`, v1 продолжает ею пользоваться через новые пути импорта. Вид собирается только из `@/kit`; деньги на экранах v2 — тиыны (`bigint`) через `Money`.

**Tech Stack:** Next.js 16.4.3, React 19, Tailwind 4, `@/kit`, vaul, sonner; vitest, Playwright (`e2e-v2/`, проект `flows` с пересевом).

**Spec:** `docs/superpowers/specs/2026-11-12-frontend-redesign-design.md` — разделы 4–7, 10–12, уточнения в разделах 14 и 15. Правила вида: `docs/design/v3/rules.md`, `checklist.md`, справочник `components.md`, эталоны `docs/design/v3/reference/`.

## Global Constraints

- Пути — от `apps/web/`, если не сказано иное. Ветка `frontend-v2`, без worktree, без `git stash`, без пуша. Коммит только своих файлов по явным путям (`git diff --cached --stat` перед коммитом).
- v1 (`src/app/(legacy)`, `src/ui`) заморожен: поведение не менять. Разрешено одно: механически заменить путь импорта, когда чистая логика переезжает в `src/features/` (без изменения кода логики; её тесты переезжают вместе с ней). Сигнатуры экспортируемых функций модулей не менять; новое — добавлять рядом.
- Экраны v2: компоненты только из `@/kit`; тексты только из `ru.app` (новые файлы зон: `buyer.ts`, `deal.ts`, `chat.ts`, `profile.ts`); адреса только через `to()`; версии — только `desktop:` / `mobile:`; server actions — в `actions.ts` рядом с экраном, через `action()` из `@/platform/action`: zod-схема, затем `requireUser("CLIENT")` (или нужные роли) первой строкой. Формы — `useActionForm` + `onSubmit`. Сторожа `src/kit/guards.test.ts` обязательны.
- Экран: один `<h1>`, не больше одного `data-primary-action`, «Назад» с названием родителя на вложенных, первая карточка отвечает «что сейчас и что от меня нужно» (`NowNext`). Телефон: главное действие в `ActionDock`, подтверждения и пояснения — шторкой; компьютер: `Split` / `Narrow`, подтверждения — диалогом, пояснения — поповером.
- Тексты: нет слов «демо», «комиссия», «эскроу», «тестовый», «платформа» (пишем «сервис»). Покупатель видит «Защита сделки (2%)» и «деньги в банке под защитой»; нигде не сказано, что деньги проходят через счета сервиса. Главное действие покупателя называется «Заказать мебель».
- Деньги: суммы — тиыны, целые; показ только через `Money` из kit; формулы — только `computeDealMoney` / `partyEstimate` / `projectMoney` из `src/modules/payments` (ничего не считать на экране). Блок денег и история денег строятся из журнала (`moneyBlock`, `moneyHistory` в `getDealView`), не из статуса.
- Демо в v2 не переносится: ни пометок «тестовый платёж» (`isTest`, `isDemo`), ни баннеров, ни демо-персон, ни настроек, доступных только при `DEMO_MODE`.
- Возможности за флагами (`preContractFlows`, `ai`, `materialsCalculator`, `dealPortfolio`, `inspiration`, `clientPhoneConsent`, `publicShowcase`) в этом этапе не переносятся: v2 строит путь ТЗ при выключенных флагах. Исключение — `reviews` (форма отзыва входит в этап, показывается при включённом флаге). Если флаг включён, а экрана v2 нет, соответствующий блок в v2 не показывается (перенос — этап 6).
- Права проверяет модуль (чужое — NOT_FOUND → 404 на странице). Имя и контакты мастера — только то, что отдаёт модуль (`«Исполнитель №N»` до оферты, `dealContacts` после).
- Без `any`, без `console.log`. Хуки запрещают пути и команды с подстрокой «точка + env» и чтение `.pem` / `.key`.
- Базы: только `senim_v2web_test` (тесты) и `senim_v2web_e2e` (dev-сервер 3110 и e2e) на `localhost:5442`. Базы `senim`, `senim_test`, `senim_e2e` не трогать даже чтением.

## Harness

Как на этапе 2: на задачу — бриф → исполнитель (модель указана в заголовке задачи) → точечные проверки и снимки → ревью кода и ревью вида по снимкам (телефон и компьютер, обе темы) → до трёх кругов правок → запись в журнал. Одновременно не больше трёх исполнителей; задачи одной группы, не делящие файлы, идут параллельно. Решения по ходу — строками `Ruling` в журнале.

## Review Focus

1. **Двойное нажатие и повтор** на изменяющих действиях (принять цену, оплатить, подписать, отменить, открыть спор, отправить сообщение): один эффект — тест на каждое действие v2.
2. **Сделка в неожиданном состоянии:** открыт спор, сделка отменена или возвращена, другая сторона ещё не подписала, оплата ждёт подтверждения оператора (`manual`) — экран показывает одно понятное «что сейчас», а не пустоту и не кнопку, которая вернёт ошибку.
3. **Чужое и несуществующее:** чужая заявка, предложение, сделка, документ, диалог — 404, без утечки существования; человек с двумя ролями, открывший сделку в «не той» роли, получает понятное переключение, а не 404.
4. **Скрытые контакты:** до оферты в предложении, торге и чате нет имени, телефона, Instagram, почты мастера ни в тексте, ни в `alt`, ни в метаданных; после оферты — видны обеим сторонам.
5. **Длинные и пустые данные:** длинное название заявки и адрес, 0 предложений, 30 предложений, пустой чат, сообщение в 2000 знаков, сумма в десятки миллионов — раскладка не ломается на 360 px и при шрифте 200 %.
