# Глоссарий

| Термин | В коде | Значение |
|---|---|---|
| Заказчик | `Role.CLIENT` | Тот, кто заказывает мебель |
| Исполнитель | `Role.EXECUTOR`, `ExecutorProfile` | Самозанятый, ИП или ТОО. Для заказчика — «Исполнитель №N» (`publicNumber`) или наименование — по режиму показа |
| Режим показа исполнителя | `PlatformSetting["companies.executorIdentity"]`, `companies.executorDisplay` | «Имя скрыто» (`HIDDEN`, по умолчанию): «Исполнитель №N», город и район. «Имя показано» (`SHOWN`): наименование и полный адрес. Включает оператор в демо (ADR-006). Телефон не показывается ни в каком режиме |
| Адрес мастерской | `ExecutorProfile.city`, `district`, `streetAddress` | Адрес мастерской или офиса исполнителя: в анкете и профиле; заказчик видит город и район, улицу — только в режиме «имя показано» |
| Оператор | `Role.OPERATOR` | Сотрудник платформы: модерация, справочники, споры, сверка. Не совмещается с другими ролями |
| Замерщик площадки | `Role.MEASURER`, `SiteMeasurement` | Сотрудник площадки (сценарий 2, ADR-005): по назначению оператора снимает размеры, заметки и фото до предложений исполнителей. Как оператор, не совмещается с другими ролями |
| Выданные роли | `User.roles` | Роли человека на одном аккаунте (ADR-004): заказчик и исполнитель могут быть у одного человека |
| Активная роль | `Session.activeRole`, `CurrentUser.role` | Роль, в которой человек действует в этой сессии; все права — по ней. Переключается в шапке; новый вход — в последней активной роли (`User.role`) |
| Знакомство | `/welcome`, `identity.recordOwnIdentity` | Шаг сразу после первого входа: ФИО и ИИН один раз (нужны для договора), потом не меняются пользователем |
| Самосделка | — | Заказ у самого себя (один человек в ролях заказчика и исполнителя). Запрещена: нет отклика, прямого запроса, сделки и отзыва себе |
| Сегмент | `Segment` | Эконом / Комфорт / Премиум. Исполнителю ставит оператор; заявке — заказчик по подсказке правил |
| Заявка | `Request` | Что нужно заказчику. Режим `TENDER` (всем исполнителям сегмента) или `DIRECT` (одному, «Хочу похожее») |
| Отклик | `Offer` | Предложение исполнителя на заявку: цена, срок, гарантия, условия замера. Один на пару «заявка — исполнитель» |
| Замер | `Measurement` | Выезд замерщика исполнителя после выбора отклика; даёт итоговую цену |
| Сценарий до договора | `PreContractFlow`, `Request.preContractFlow` | Порядок шагов от предложений до договора (ADR-005): замер исполнителем, замерщик площадки, договор до замера, залог за замер, онлайн-замер. Настройка площадки; заявка запоминает сценарий при отправке |
| Утверждение проекта | `Project` | Общий шаг всех сценариев: исполнитель отправляет проект (материалы, расшифровка стоимости, срок, гарантия, итоговая цена), заказчик утверждает или просит изменить; новая версия — новая строка. Цена утверждённого проекта — цена договора |
| Залог за выезд | `MeasureDeposit` | Сценарий 4: заказчик платит исполнителю напрямую и отмечает, исполнитель подтверждает. Засчитывается в первую оплату по договору на площадке; через площадку деньги не идут |
| Повторный отклик | `OfferRetry`, `Offer.round` | Разрешение оператора (с причиной) отклонённому исполнителю откликнуться на ту же заявку ещё раз (№16) |
| Условия замера | `MeasurementTerms` | `FREE`, `INCLUDED` (в стоимости заказа), `FEE_IF_NO_DEAL` (плата за выезд, если сделка не состоялась; напрямую исполнителю) |
| Сделка | `Deal` | Договор подряда по выбранному отклику. Ядро `deal-core` не знает, что это мебель |
| Этап | `Stage` | Часть работы с суммой и моментом оплаты (`PaymentDue`) |
| Аванс | `PaymentDue.ON_START` | Оплата этапа до его начала |
| Оплата этапа | `StagePayment` | `DUE → MARKED_PAID` (заказчик: «оплатил») `→ CONFIRMED` (исполнитель: «получил», или банк раскрыл транш) |
| Акт этапа | `Document.kind = STAGE_ACT` | PDF о приёмке этапа, подписывают обе стороны |
| Договор | `Document.kind = CONTRACT` | PDF договора подряда; единственное место, где раскрыт ИИН/БИН исполнителя (и наименование/ФИО, если режим показа — «имя скрыто») |
| Чат отклика | `Message`, `companies.getChat` | Переписка заказчика и исполнителя по отклику, продолжается в сделке; контакты маскируются. После завершения сделки открыт; оператор может закрыть его с причиной (`Offer.chatClosedAt`) и открыть снова |
| Автоприёмка | задача `deal-core.autoAcceptStage` | Сданный этап принимается сам через `AUTO_ACCEPT_DAYS`, если заказчик молчит |
| Спор | `Dispute` | Разбирает оператор. Структура: причина, позиции сторон, вложения, решение, обоснование |
| Режим оплаты | `PaymentMode` / `RailMode` | `MANUAL` (`manual`) — напрямую исполнителю; `ESCROW_SIMULATOR` — симулятор банка для показа; `BANK` — эскроу-счёт банка |
| PaymentRail | `src/modules/payments/rail.ts` | Точка подключения банка: счёт, реквизиты, пополнение (вебхук), раскрытие транша, возврат, выписка |
| Транш | `PaymentOperation.kind = RELEASE` | Раскрытие части эскроу исполнителю по этапу |
| Журнал аудита | `AuditEvent` | Только добавление. `scope` («deal:<id>») собирает всю историю сделки |
| Демо-режим | `DEMO_MODE=true` | Демо-персоны, «Сбросить демо», страница показа банку, переключатель режима оплаты, переключатель показа исполнителя |
