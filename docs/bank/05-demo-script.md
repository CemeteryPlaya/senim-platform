# 05. Сценарий показа банку (10 минут)

Показ ведётся на демо-стенде с тестовыми данными (`DEMO_MODE=true`). Опорная страница — `/bank-demo`: на ней семь шагов полного цикла, у каждого шага кнопка «Войти как … и открыть», которая входит под нужной демо-персоной и открывает экран шага. Записи для шагов страница находит по их состоянию в базе.

Номера заявок и сделок ниже — для свежих демо-данных (после «Сбросить демо» нумерация начинается заново). Персоны и данные — `src/demo/data.ts`, `docs/agents/DEMO_DATA.md`.

## Подготовка (за 15 минут до встречи, около 5 минут работы)

Все сделки в демо-данных — в режиме прямой оплаты (`manual`). Эскроу показывается на новой сделке, которую создают после включения симулятора. Создать её заранее, чтобы на встрече показывать только пополнение и транш.

1. **Сброс.** Динара (оператор) → `/operator/demo` → «Сбросить демо» → «Да, сбросить». Все выйдут; откроется выбор персоны. Локально то же делает `npm run db:reset` (или `DEMO_MODE=true npx prisma db seed`).
2. **Режим оплаты.** Динара → `/operator/demo` → «Режим оплаты для новых сделок» → «Симулятор банка (эскроу)» → «Сохранить режим». Влияет только на новые сделки: сделки из демо-данных остаются в прямой оплате.
3. **Итоговая цена после замера.** Нурлан Абдрахманов (ИП «Дала Мебель») → «Замеры» (`/executor/measurements`) → заявка №17 «ТВ-зона» → «Итоговая цена, ₸» (например, 460 000) → «Внести итоговую цену».
4. **Сделка в эскроу.** Данияр Ахметов → заявка №17 → «Порядок оплаты»: «Аванс 50% на материалы» → «Согласен, перейти к договору». Создаётся новая сделка (на свежих данных — №15) в режиме «Эскроу-счёт (симулятор банка)».
5. **Подписи.** Данияр → сделка → договор → «Подписать» → «Я подписал — проверить». Затем Нурлан → та же сделка → «Подписать» → «Я подписал — проверить». Сделка переходит в «ожидание пополнения».
6. **Проверка.** Открыть `/bank-demo`: шаг 5 «Пополнение эскроу» показывает новую сделку и персону Данияра. Открыть сделку под Данияром: видны реквизиты счёта и кнопка «Открыть банк-симулятор» (если реквизитов нет — обновить страницу: счёт открывается при показе сделки).
7. Держать открытыми две вкладки: `/bank-demo` и сделку №15 под Данияром. Для смены персоны — `/demo`.

## Что не говорить

- Не называть режим `manual` «эскроу» или «безопасной оплатой»: в нём деньги идут напрямую исполнителю, формулировка — «оплата по этапам под контролем».
- Не называть симулятор банком и не показывать его суммы как реальные деньги.
- Не утверждать, что SIGEX, SMS-провайдер или банк уже подключены: сейчас это интерфейсы с моками.

## Запасной план

| Что случилось | Что делать |
|---|---|
| Не успели подготовить эскроу-сделку | Показать шаг 5 на `/bank-demo`: он сам предлагает «Включить симулятор». Пройти подготовку п. 2–5 на встрече (около 3 минут) или рассказать цикл по диаграммам `03-escrow-integration.md`, раздел 9 |
| Кнопка «Открыть симулятор банка» на `/bank-demo` ведёт на «страница не найдена» | Открыть сделку под заказчиком и нажать «Открыть банк-симулятор» на экране сделки (у кнопки шага сейчас неверный адрес — передано интегратору) |
| У эскроу-сделки нет реквизитов | Обновить страницу сделки: счёт открывается при её показе. Локально можно запустить `npm run jobs` |
| Данные изменены прошлым показом | Динара → `/operator/demo` → «Сбросить демо», затем подготовка заново |
| Сайт просит пароль | Демо-стенд в production закрыт паролем показа (`DEMO_ACCESS_PASSWORD`), имя пользователя любое |
| Нет сети или стенд недоступен | Локальный запуск (README, «Локальный запуск»), затем тот же сценарий на `http://localhost:3100` |
| Мало времени | Только три блока: заявка и отклики (анонимность), договор с хэшем, эскроу-пополнение с повтором вебхука и журнал |
