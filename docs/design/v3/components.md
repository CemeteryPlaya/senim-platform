# Справочник компонентов `@/kit`

Для авторов экранов нового интерфейса (v2). Всё ниже взято из кода `apps/web/src/kit/`; чего здесь нет, того в kit нет.
Правила вида и поведения — в `rules.md` и `checklist.md` рядом; эталоны — в `reference/`. Живые образцы всех компонентов — на `/v2/ui-kit` (`apps/web/src/app/(app)/v2/ui-kit/`).

## Как пользоваться

- **Импорт только из `@/kit`** (`import { Button, Card } from "@/kit"`), не `@/kit/<файл>` (сторож, правило 11). Исключения — модули, которых в `@/kit` нет намеренно: `@/kit/theme` (`getTheme()` читает куки — только сервер), `@/kit/fonts`, `@/kit/tokens`; в тестах — `@/kit/test-utils`. Внутренний `button-styles` снаружи не импортируется.
- **Тексты только из `ru`** (`ru.app.<экран>.*`, файлы в `apps/web/src/i18n/ru/app/`), в разметке и строках кириллицы нет. Ключи `ru.app.requests.*` в примерах ниже условные: свои добавляйте рядом с экраном.
- **Адреса только через `to()`** (`import { to } from "../_shell/paths"`: `to("/deals/42")` → `/v2/deals/42`) и `legacy()` для ссылки в v1.
- **Устройство** — телефон или компьютер — различают варианты `desktop:` и `mobile:` (атрибут `data-device` на `<html>`), а не ширина окна. Серверный экран получает устройство так: `const device = await getDevice()` (`@/platform/device`) и передаёт его в компоненты, которым оно нужно (`ConfirmDialog`, `Explain`, `Toaster`).
- **Одно главное действие на экран.** Главное — `Button`/`ButtonLink` без `variant` (или `variant="primary"`). Остальные — `secondary`, `quiet`, `danger`.
- Серверные компоненты (без `"use client"`): `Stack`, `Split`, `Narrow`, `Section`, `Card`, списки, `StatusChip`, `Money`, `Progress`, `PhotoSlot`, `PageTitle`, `BackLink`, `WizardHeader`, `NowNext`, `FirstSteps`, `EmptyState`, `HelpBlock`, `ButtonLink`, `Skeleton`, поля (`TextField`, `TextArea`, `Select`, `Checkbox`, `RadioCard`, `RadioGroup`), `Segmented`. Клиентские (`"use client"`): `Button`, `Sheet`, `Dialog`, `ConfirmDialog`, `Popover`, `Explain`, `Toaster`. Клиентский компонент можно ставить в серверный экран; серверный компонент без обработчиков можно ставить и в клиентский.
- Добавлены для экранов гостя и входа (все серверные, кроме хука `useActionForm`): `Notice`, `HiddenField`, `CodeField`, `PhoneField`, `Chips`, `FilterList`, `Pagination`, `ActionDock`, `WorkCard`, `Rating`, `Columns`, `TextLink`; клиентские — только `ChipsRail` (внутри `Chips`: прокрутка ленты к выбранному чипу), `useActionForm` (`_shell/form.ts`) и `error.tsx` группы.

### Что запрещают сторожа

Сторожа (`src/kit/guards.test.ts`) читают исходники `src/kit/**` и `src/app/(app)/**`; нарушение — красный тест.

1. Вес шрифта не выше 600: нет `font-bold`, `font-extrabold`, `font-black`, `fontWeight` 700 и выше.
2. Нет сырых цветов: ни hex, ни `rgb()`, `hsl()`, `oklch()` — только токены `tokens.css` (`text-ink`, `bg-surface`…).
3. Нет произвольных значений Tailwind: `text-[15px]`, `rounded-[10px]`, `bg-[#fff]`, `max-w-(--x)` запрещены; разрешены токены и `data-[state=open]:` как вариант.
4. Нет импортов старого интерфейса: `@/ui`, `@/app/(legacy)`, относительные пути в них.
5. В экранах нет сырых `<button>`, `<input>`, `<select>`, `<textarea>` — только компоненты kit.
6. Адреса строятся через `to()`/`legacy()`: нет `href="/..."`, `redirect("/...")`, `router.push("/...")` и `router?.push("/...")` с литералом, `href={{ pathname: "/..." }}`; `push`/`replace`/`prefetch` не деструктурируются из `useRouter()` (в том числе в несколько строк) — пишите `router.push(to("/..."))`.
7. Нет кириллицы в разметке и строках (комментарии по-русски можно).
8. В `ru.app` нет слов «демо», «комиссия», «эскроу».
9. Нет `sm:`, `md:`, `lg:`, `xl:`, контейнерных `@md:`, `@media (width…)`, `matchMedia`, `innerWidth`, `clientWidth`, `screen.width` — версии различают `desktop:` и `mobile:`.
10. `button-styles` импортируют только файлы kit.
11. Вне `src/kit` (и в тестах) kit импортируется только как `@/kit`; исключения — `@/kit/theme`, `@/kit/fonts`, `@/kit/tokens`, а в тестах ещё `@/kit/test-utils`.
12. В `src/app/(app)/**` нет отрицательных полей (`-ml-6`, `-mx-4`, `mobile:-mt-2`): выход за поле — дело компонента kit (`TextLink`, `Chips`), а не обхода в разметке экрана. Сдвиги `-translate-x-…` не поля.

Отдельно: анимируются только `transform` и `opacity`; размеры текста, радиусы, тени, цвета — токены; контролы не ниже 48 px (на компьютере вторичные `sm` — 36 px).

### Токены и утилиты вида (пересмотр 15.11.2026)

Значения — `src/kit/tokens.css` (цвета дублируются в `src/kit/tokens.ts`: `TOKENS`, `TRANSLUCENT`, `GLASS`); образцы — на `/v2/ui-kit` (разделы «Цвета», «Типографика», «Формы и тени», «Стекло»). Правила применения — `rules.md`.

**Цвета** (`bg-*`, `text-*`, `border-*`): `canvas`, `surface`, `raised`, `ink`, `muted`, `line`, `line-strong`, `fill` (полупрозрачный ink — вторичная кнопка, нейтральный чип, монограмма, дорожка; работает на любом фоне), `fill-strong` (плотнее: наведение на вторичную кнопку, нажатие строки, линза активной вкладки; на нём только ink), `action-hover` (наведение главной: осветление, в тёмной — притемнение), `on-inverse` (графитовый текст инверсной кнопки), `track`, `bubble`, `action` / `on-action`, `accent` / `accent-soft`, `danger` / `on-danger` (цифры бейджа на сплошном `danger`: белые в светлой теме, графитовые в тёмной) / `danger-soft`, `warn` / `warn-soft`, `focus`, `scrim`, `photo-fallback` (место фото до загрузки), `on-photo` (белый: текст на затемнённом фото, инверсная кнопка на тёмном фото), `glass-secondary` (вторичный текст на стекле — вместо `muted`).

**Текст** (`text-*` ставит размер, межстрочный, трекинг и, где указан, вес 600): `display-xl` 64 (только `desktop:`), `display` 40, `display-amount` 40 (сумма-герой, с `tabular-nums`), `title` 34 / 40 (`PageTitle`), `amount` 28 (суммы в карточках, `Stat`), `title-2` 22 (`Section`, `Dialog`, `Sheet`), `lead` 21, `headline` 17 / 600 (заголовок карточки, строки), `body` 17, `sub` 15, `small` 13 / 500; `text-currency` — «₸» на 0,6 размера суммы (`<Money large />` ставит его сам). Ширина абзаца на компьютере — `max-w-measure` (68ch). Шрифт — Inter с осью `opsz` (`src/kit/fonts.ts`), `font-optical-sizing: auto` на `body`.

**Радиусы** (`rounded-*`): `card` 20 / 22, `control` 16 / 12, `field` 12, `thumb` 12 (миниатюра `size-thumb` 56 px), `photo` = `card` − `photo-inset` (фото в карточке с отступом `p-photo-inset`, 8 px — концентрично), `small` 6 (флажок, фокус ссылки), `chip` и `bar` — капсулы, `sheet` 32 (неполная высота) / `sheet-full` 24, `full` — круг.

**Тени** (`shadow-*`, значения по теме, в тёмной плотнее): `float` (панель, кнопка-док, тост), `overlay` (меню, поповер, окно), `sheet` (шторка), `hover` (только `desktop:hover:` у кликабельной карточки).

**Стекло** (утилиты; одна на элемент, никогда стекло внутри стекла):

| Утилита | Где | Что внутри |
|---|---|---|
| `glass-regular` | панель вкладок, круглые кнопки 48 px (колокольчик и «…» на телефоне) | тон по теме 78 % / 80 %, размытие 24 px, насыщенность 180 %, блик по верхней кромке, контур 0,5 px, кромка-градиент (`::before`), тень `float`. Свою рамку и `shadow-*` рядом не ставить |
| `glass-thick` | меню, поповер со списком (`Popover material="glass"`), меню аватара, тосты | 86 % / 88 %, размытие 40 px, тень `overlay`; при уменьшении прозрачности — сплошной `raised` |
| `glass-bar` | шапка компьютера, закреплённая шапка переписки (`mobile:sticky-head mobile:glass-bar`) | материал regular без контура и тени; вместо линии снизу — «растворение» содержимого под шапкой при прокрутке (`::after`); элемент должен быть `sticky`/`fixed` |
| `glass-clear` | чипы, цены, капсулы **поверх фото** | тёмная подложка 28 %, размытие 12 px, белый текст 600 с тенью; **только** над `scrim-photo` |
| `scrim-photo`, `scrim-photo-start` | пустой `<div aria-hidden>` поверх `<img>` и под текстом, в контейнере `relative` | затемнение 55 %: нижняя четверть (у `-start` — от левого нижнего угла) полностью, к 60 % (75 %) — прозрачно, спад плавный (S-кривая по семи точкам, без полосы). Белый текст и капсулы — в зоне полного затемнения |
| `bar-underlay` | подложка оболочки телефона (`MobileShell`) | «растворение» содержимого у нижнего края: тон фона густеет к низу (72 % у края), не плита — стекло панели видно; видна только при панели вкладок или доке; при уменьшении прозрачности и увеличении контраста — сплошная |
| `dock-float`, `composer-bar` | док (`ActionDock`), поле переписки (`ChatComposer`) на телефоне | док без плиты: тень `float` у главной кнопки; поле переписки — сплошная полоса фона с растворением ленты над ней (не стекло) |
| `photo-frame` | обёртка фото | фон `photo-fallback`, `overflow: hidden`, внутренний контур 1 px (белый шкаф не сливается с белой карточкой) |

Запасные виды стекла встроены: без `backdrop-filter` — почти сплошное (96 %); `prefers-reduced-transparency` — сплошное (`surface`/`raised`), форма и тень остаются; `prefers-contrast: more` — сплошное с границей `ink`; `forced-colors` — системная граница. `glass-regular`/`glass-thick` ставят `position: relative` с нулевой специфичностью — `sticky`/`fixed`/`absolute` элемента сильнее. Текст на стекле — `text-ink` и `text-glass-secondary`.

## Раскладка

Серверные компоненты. Брейкпоинтов нет: узкое окно компьютера остаётся компьютерной раскладкой.

### `Stack`

Вертикальный поток с отступом по шкале.

| Проп | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `gap` | `"tight" \| "group" \| "section"` | `"group"` | 8 px · 12 px (карточки одной группы) · 24 px телефон / 32 px компьютер (между разделами) |
| `className` | `string` | — | Дополнение классов |
| `children` | `ReactNode` | — | Содержимое |

### `Split`

Две колонки на компьютере (1,5 : 1, выровнены по верху), на телефоне — одна: сначала `main`, затем `aside`.

| Проп | Тип | Смысл |
|---|---|---|
| `main` | `ReactNode` | Основная колонка (слева) |
| `aside` | `ReactNode` | Боковая колонка (справа); на телефоне уходит вниз |

### `Sidebar`

Узкая левая колонка и основная: `aside: ReactNode`, `device: Device`, `children`. Компьютер: `aside` шириной 15 rem (токен `--sidebar-width`) прилипает при прокрутке (`sticky-aside`), основная колонка на остальную ширину, зазор 24 px, по верху. Телефон: выводятся **только** `children` — `aside` в разметку не попадает (версию выбирает экран по `device`, скрытого дубля в DOM нет). Для списков фильтров каталога (`FilterList`). У `aside` есть доступное имя — у списка фильтров это его заголовок (`<nav aria-label>` у `FilterList`); если кладёте в `aside` другое содержимое, дайте ему имя сами (`<nav aria-label>` или `<section aria-label>`).

```tsx
<Sidebar device={device} aside={<FilterList title={t.type} items={typeItems} />}>
  {/* основная колонка */}
</Sidebar>
```

### `Narrow`

Ограничивает ширину до 560 px на компьютере (по левому краю); на телефоне ничего не делает. Для форм и строк «подпись — значение». Проп один: `children`.

### `Section`

Раздел экрана: `<h2>` и содержимое через зазор группы. Заголовок стоит ровно по левому краю карточек.

| Проп | Тип | Смысл |
|---|---|---|
| `title` | `string` | Текст заголовка раздела |
| `id` | `string?` | Якорь: `id` заголовка для ссылок `#id` (раздел подписан им) |
| `children` | `ReactNode` | Содержимое |

```tsx
<Stack gap="section">
  <PageTitle title={t.title} />
  <Split
    main={<Section title={t.sectionRequests}>{/* карточки */}</Section>}
    aside={<HelpBlock items={helpItems} supportEmail={brand.support.email} />}
  />
</Stack>
```

## Кнопки

### `Button` (клиентский) и `ButtonLink` (серверный)

`Button` — действие на экране; `ButtonLink` выглядит так же, но это ссылка (переход на другой экран). Тип пропсов `Button` — обычный `<button>`; `ButtonLink` — пропсы `next/link` плюс вид.

| Проп | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `variant` | `"primary" \| "inverse" \| "secondary" \| "quiet" \| "danger"` | `"primary"` | Вид. `primary` — единственное главное действие экрана. `inverse` — та же главная, но в «тёмном» контексте поверх фото (первый экран лендинга): белая заливка `on-photo`, графитовый текст `on-inverse`, одинаковая в обеих темах; наведение — затемнение на 8 % (`inverse-hover`), не прозрачность. Только поверх затемнённого фото, не на светлом фоне страницы |
| `size` | `"md" \| "sm"` | `"md"` | `md` — 48 px. `sm` — только у не-главных: 48 px на телефоне, 36 px на компьютере. `primary` и `inverse` с `sm` не собираются типом |
| `full` | `boolean` | `false` | На всю ширину контейнера |
| `flush` | `boolean` | `false` | Только у `quiet`: без боковых отступов — подпись по левой линии содержимого (как текст и `TextLink` рядом); высота касания прежняя, наведение — подчёркивание. Образец — «Отправить ещё раз» на шаге кода (`_shell/ResendCode`). У других вариантов не действует |
| `pending` | `boolean` | `false` | Только у `Button`. Идёт действие: индикатор вместо подписи (ширина не меняется), `aria-busy`, нажатие и повторная отправка формы гасятся, фокус остаётся |
| `type` | `"button" \| "submit" \| "reset"` | `"button"` | Только у `Button`; для отправки формы указывайте `type="submit"` |

Заметки:

- Главная кнопка (`primary` или `inverse`) помечается `data-primary-action`; тесты считают «одна на экран». Не ставьте две — и не ставьте `inverse` рядом с `primary`.
- `danger` — необратимое действие; само необратимое действие подтверждайте через `ConfirmDialog`.
- Подпись — глагол, называющий результат («Создать заявку»), не «Ок».
- `buttonClasses(options)` отдаёт классы кнопки для случаев, когда элемент не `<button>` и не `<Link>`.

```tsx
<Stack>
  <ButtonLink href={to("/requests/new")}>{t.create}</ButtonLink>
  <Button variant="secondary" size="sm" onClick={save} pending={saving}>
    {t.saveDraft}
  </Button>
</Stack>
```

## Поля

Серверные (без `"use client"`): их можно рендерить в серверном экране и в клиентском компоненте. У всех обязательны `label` (видимая подпись) и `name`; `error` показывается сразу под полем (`role="alert"`, связь через `aria-describedby`, рамка `danger`). Остальные пропсы — как у соответствующего нативного элемента (кроме `name`, который здесь обязателен и определён в `FieldProps`). Высота поля 48 px.

| Компонент | Нативная основа | Особенности |
|---|---|---|
| `TextField` | `<input>` | `type`, `inputMode`, `autoComplete` и прочее передаются как есть |
| `TextArea` | `<textarea>` | `rows` по умолчанию 4; высота растёт по содержимому от трёх строк; без уголка изменения размера |
| `Select` | `<select>` | Подсказка пустого выбора — `<option value="">`: пока выбран он, текст muted |
| `Checkbox` | `<input type="checkbox">` | `label` справа от квадрата; весь ряд — цель касания |
| `RadioCard` | `<input type="radio">` | `description?: string` — вторая строка под подписью (15 px `muted`), связана с радио через `aria-describedby`; без неё разметка прежняя. Вариант выбора карточкой; выбранный выделен рамкой цвета действия. `label` и `name` обязательны; ошибки нет — она у группы |
| `RadioGroup` | `<fieldset>` | `legend: string`, `error?: string`, `legendHidden?: boolean`, `children` (набор `RadioCard`). `legendHidden` — подпись только для экранного диктора (`sr-only`, остаётся в разметке): когда вопрос уже задан заголовком экрана (шаг входа «Вы покупатель или мастер?»); ошибка группы видна как обычно |

Общие пропсы `FieldProps`:

| Проп | Тип | Смысл |
|---|---|---|
| `label` | `string` | Подпись поля |
| `name` | `string` | Имя поля формы |
| `error` | `string?` | Текст ошибки (из `ru`, код ошибки сервиса → текст на стороне web) |

```tsx
<Narrow>
  <Stack>
    <TextField label={t.title} name="title" autoComplete="off" error={errors.title} />
    <RadioGroup legend={t.kind} error={errors.kind}>
      <RadioCard label={t.kindKitchen} name="kind" value="kitchen" />
      <RadioCard label={t.kindWardrobe} name="kind" value="wardrobe" />
    </RadioGroup>
    <Button type="submit" pending={pending}>{t.submit}</Button>
  </Stack>
</Narrow>
```

## Карточки и списки

### `Card`

Светлая карточка без рамки и тени, радиус 20 px (телефон) / 22 px (компьютер), `rounded-card`. Три вида (разбор 3.6).

| Проп | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `as` | `"div" \| "section" \| "article" \| "li"` | `"div"` | Тег |
| `variant` | `"plain" \| "hero" \| "grouped"` | `"plain"` | `plain` — обычная. `hero` — одна на экране (текущая сделка, сумма, первый экран профиля мастера): отступ 24 px, тело — колонка с зазором 16 px, сверху место под фото-обложку 16:9 (`cover`); сумма в теле — `text-display-amount` с `<Money large />`; главная кнопка на компьютере — внутри. `grouped` — сгруппированный список: без отступа, `overflow-hidden` (подсветка строк не выходит за скругление), внутри `List` |
| `padded` | `boolean` | `true` | Только у `plain`: внутренний отступ 16 px; `false` — когда внутри списки или фото во всю ширину |
| `cover` | `ReactNode?` | — | Только у `hero`: обложка — `<img>`/`next/image` (растягивается `object-cover`) в рамке `photo-frame` 16:9 во всю ширину сверху (радиус карточки) |
| `interactive` | `boolean` | `false` | Карточка целиком кликабельна: на компьютере при наведении — подъём 2 px и тень `hover` за 200 мс; в покое и на телефоне тени нет |
| `className` | `string` | — | Дополнение классов |

### `List`, `ListRow`, `ListItem`

`List` — `<ul>`; кладётся в `Card` (обычно `padded={false}`). Строки — только `ListRow` или `ListItem` (голый `<li>` нельзя: у него не будет разделителя).

`ListRow` — строка «подпись — значение»:

| Проп | Тип | Смысл |
|---|---|---|
| `label` | `ReactNode` | Подпись: `muted`, если есть значение; у строки-ссылки без значения — `ink` (это и есть её содержимое) |
| `value` | `ReactNode?` | Значение справа, `ink`. Сумма — `<Money>`, оценка — `<Rating>` (корень — `span`, годится значением) |
| `href` | `string?` | Есть адрес — вся строка ссылка, справа шеврон (через `to()`) |
| `chevron` | `boolean?` | `true` по умолчанию; `false` — без шеврона у якоря на этой же странице (оглавление) |
| `stacked` | `boolean?` | Подпись над значением (подпись 15 px `muted`, значение 17 px `ink`, переносится) — для длинных значений: адрес, описание |
| `action` | `(formData: FormData) => void \| Promise<void>`? | Строка-действие: вместо ссылки `<li><form action><button type="submit">` с серверным действием; вид, разделитель и фокус как у строки-ссылки, без шеврона. Не сочетается с `href`. Подпись — любой `ReactNode` (строка из нескольких линий) |
| `fields` | `Record<string, string>?` | Скрытые поля формы строки-действия, например `{ id }` |
| `leading` | `ReactNode?` | Слева от подписи: миниатюра 56 px (`photo-frame size-thumb rounded-thumb` с фото) или `<Monogram size="md" />`. Строка не ниже 56 px, разделитель — от начала текста |
| `detail` | `ReactNode?` | Вторая строка под подписью (15 px, muted, не больше двух строк); подпись тогда — заголовок строки (`headline`, ink) |

Шеврон строки-ссылки — 16 px `muted`; нажатие строки — заливка `fill-strong`.

`ListItem` — обёртка для строки со своей разметкой (`children`), даёт разделитель с отступом 16 px; у последней строки разделителя нет. У `ListRow` с `leading` разделитель рисует колонка текста — от начала текста, какой бы ширины ни была миниатюра или монограмма (`ListItem inset="none"`).

```tsx
<Card padded={false}>
  <List>
    <ListRow label={t.price} value={<Money tiyn={deal.priceTiyn} />} />
    <ListRow label={t.master} value={master.name} href={to(`/masters/${master.id}`)} />
  </List>
</Card>
```

## Статусы, деньги, прогресс, фото, загрузка

### `StatusChip`

Статус сделки или заявки: капсула 28 px (компьютер 26 px), текст 15 px / 500, слева точка 8 px цвета состояния (скрыта от диктора). Если у всех строк списка один статус — не показывайте его в строке.

| Проп | Тип | Смысл |
|---|---|---|
| `tone` | `"accent" \| "neutral" \| "warn" \| "danger"` | `neutral` — информационный («Идёт сделка», «Опубликована»): заливка `fill`, текст ink, точка muted; `warn` — от человека нужно действие; `accent` — деньги под защитой; `danger` — спор, отказ |
| `children` | `ReactNode` | Текст статуса из `ru` |

### `Money` и `formatMoney`

Сумма **в тиынах, `bigint`** (1 тенге = 100 тиын): `<Money tiyn={122400000n} />` → «1 224 000 ₸». Тиыны показываются, когда сумма не кратна 100. Никаких `number` и float.

| Проп | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `tiyn` | `bigint` | — | Сумма в тиынах |
| `tone` | `"ink" \| "inherit"` | `"ink"` | `inherit` — цвет окружения (сумма внутри вторичного текста, на фото) |
| `large` | `boolean` | `false` | Крупная сумма (герой, блок денег, сводка): знак «₸» — 0,6 размера (`text-currency`), у `ink` — muted. В строках и тексте не ставится. Текст суммы тот же (`formatMoney`) |

`formatMoney(tiyn: bigint): string` — та же строка без разметки (для `aria-label`, тостов). Суммы считает сервис `deal` (`ComputeDealMoney`), экран их только показывает.

### `Progress`

Полоса прогресса, 4 px, `role="progressbar"`.

| Проп | Тип | Смысл |
|---|---|---|
| `value` | `number` | Текущее значение (ограничивается 0…`max`); не число — ничего не рисуется |
| `max` | `number` | Максимум; `max <= 0` или не число — ничего не рисуется |
| `label` | `string` | Подпись для диктора |

### `PhotoSlot`

Место под фото; без `src` — ровная заглушка цвета `line`.

| Проп | Тип | Смысл |
|---|---|---|
| `src` | `string?` | Адрес снимка из хранилища файлов |
| `alt` | `string` | Описание (обязательно) |
| `ratio` | `"4/3" \| "1/1" \| "16/9"` | Соотношение сторон |

### `Skeleton`

Заготовка строк, пока грузятся данные: статичная, диктор слышит «Загрузка». Проп `lines?: number` (по умолчанию 3).

```tsx
<Card>
  <ListRow label={t.paid} value={<Money tiyn={paidTiyn} />} />
  <StatusChip tone="warn">{t.statusWaiting}</StatusChip>
  <Progress value={stage} max={5} label={t.progress} />
</Card>
```

### `Monogram`

Аватар-монограмма: круг с заливкой `fill`, текст ink 600, скрыт от диктора (имя стоит рядом текстом). Для «Исполнителя №8» — «№8» (имя скрыто, ADR-006); номер из трёх и более цифр — без «№» («1042»), из четырёх и более знаков — кеглем на ступень меньше, чтобы влезть в 36 и 44 px; для имени — первые буквы двух слов; без имени — значок человека. `monogramOf(name)` — тот же текст строкой.

| Проп | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `name` | `string \| null \| undefined` | — | Имя или публичная подпись |
| `size` | `"sm" \| "md" \| "lg"` | `"sm"` | 36 px — шапка; 44 px — строки списков и чатов; 72 px — профиль мастера |

### `NavLens` (клиентский)

«Линза» активного пункта навигации: подложка `fill-strong` (капсула или `shape="field"` при переносе пунктов) первым ребёнком позиционированного пункта (`relative isolate`); `group` — имя линзы группы: при смене пункта она переезжает пружиной без отскока (Motion `layoutId`), при `prefers-reduced-motion` — мгновенно. Скрыта от диктора — активный пункт объявляет `aria-current`. Применяется в `TabBar` и `TopNav` оболочки.

## Навигация внутри экрана

### `PageTitle`

Заголовок экрана — единственный `<h1>` (`text-title`: 34 px на телефоне, 40 px на компьютере).

| Проп | Тип | Смысл |
|---|---|---|
| `title` | `string` | Текст заголовка |
| `back` | `{ href: string; label: string }?` | Вложенный экран: ссылка на родителя над заголовком |
| `lead` | `ReactNode?` | Пояснение под заголовком (muted) |
| `onGlass` | `boolean?` | Заголовок на стекле (закреплённая шапка переписки, `glass-bar`): «Назад» и пояснение — `glass-secondary`, не muted. `Explain` в `lead` — тоже с `onGlass`. На стекле запрещены muted и accent (`contrast.test.ts`, сторож по экрану переписки) |

### `BackLink`

«‹ Название родителя» — один вид везде. Диктор слышит «Назад: …». Обычно отдельно не нужен: передавайте `back` в `PageTitle` или `WizardHeader`. Пропсы: `href: string` (через `to()`), `label: string` (название родителя, не слово «Назад»).

### `WizardHeader`

Шапка шага мастера: «Шаг N из M», полоса и заголовок.

| Проп | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `step` | `number` | — | Номер шага (округляется и ограничивается 1…`total`) |
| `total` | `number` | — | Всего шагов; не положительное — счётчик и полоса не рисуются |
| `title` | `string` | — | Заголовок шага |
| `back` | `{ href; label }?` | — | Ссылка «Назад» |
| `headingLevel` | `1 \| 2` | `1` | Уровень заголовка |

Заметки: `WizardHeader` **сам рисует `<h1>` экрана**, поэтому `PageTitle` рядом не ставят. `headingLevel={2}` нужен только когда `<h1>` на странице уже есть (как в образце витрины).

```tsx
<Stack gap="section">
  <WizardHeader step={2} total={4} title={t.stepTitle} back={{ href: to("/requests/new"), label: t.backLabel }} />
  <Narrow>{/* поля шага */}</Narrow>
  <Button type="submit">{t.next}</Button>
</Stack>
```

## Подсказки

Блоки, которые объясняют, что происходит и что делать дальше.

### `NowNext`

Первая карточка сделки или заявки: «Сейчас» и «Дальше».

| Проп | Тип | Смысл |
|---|---|---|
| `now` | `{ title: string; body?: string }` | Что происходит сейчас |
| `next` | `string?` | Что будет после: одна короткая строка |

### `FirstSteps`

Список первых шагов с полосой. Возвращает `null`, когда шагов нет или все пройдены. Проп `steps: FirstStep[]`, где `FirstStep = { label: string; done: boolean; href?: string }`. Ссылка работает только у невыполненного шага.

### `EmptyState`

Обучающий пустой экран: что здесь будет и что сделать первым.

| Проп | Тип | Смысл |
|---|---|---|
| `title` | `string` | Заголовок |
| `body` | `string` | Пояснение |
| `action` | `{ href: string; label: string }?` | **Единственное главное действие экрана** (кнопка-ссылка `primary`); без него кнопки нет |

Если `EmptyState` с `action` есть на экране, других `primary`-кнопок там быть не должно.

### `HelpBlock`

«Помощь» под содержимым главной и сделки: частые вопросы и письмо в поддержку.

| Проп | Тип | Смысл |
|---|---|---|
| `items` | `{ question: string; href: string }[]` | Вопросы-ссылки (адреса через `to()`) |
| `supportEmail` | `string` | Адрес поддержки (`brand.support.email` из `@/config/brand`) |

### `Explain`

Пояснение по нажатию — только для сложных мест (защита сделки, гарантия оплаты, где деньги, спор). Телефон — шторка с главной кнопкой «Понятно», компьютер — поповер. Клиентский.

| Проп | Тип | Смысл |
|---|---|---|
| `label` | `string` | Подпись кнопки, оформленной ссылкой («Что это?»): строчная, цвет `accent` |
| `onGlass` | `boolean?` | Ссылка лежит на стекле: ink с подчёркиванием вместо accent. Пояснение (шторка, поповер) остаётся сплошным |
| `title` | `string` | Заголовок пояснения |
| `device` | `"mobile" \| "desktop"` | Откуда брать вид |
| `children` | `ReactNode` | Текст пояснения |

Не злоупотребляйте: обычное пояснение пишется текстом рядом.

```tsx
const device = await getDevice();
// ...
<Stack>
  <NowNext now={{ title: t.nowTitle, body: t.nowBody }} next={t.next} />
  <Explain label={t.whatIsIt} title={t.protectionTitle} device={device}>
    <p>{t.protectionBody}</p>
  </Explain>
</Stack>
```

## Экраны гостя и входа

Дополнения для первых экранов (гость, каталог, профиль мастера, вход). Все — серверные компоненты, `"use client"` не нужен; клиентские только хук формы и `error.tsx`.

### `Notice`

Сообщение в потоке: плашка радиуса карточки, текст 17 px.

| Проп | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `tone` | `"info" \| "warn" \| "danger"` | — | Пара цветов: `accent`, `warn`, `danger` на своей подложке (контраст проверен) |
| `title` | `string?` | — | Короткий заголовок 17 px / 600 |
| `live` | `boolean` | `false` | `role="alert"`: сообщение появилось после загрузки (ответ сервера), диктор читает сразу |
| `children` | `ReactNode` | — | Текст |

Плашка «сервис недоступен» в оболочке — `Notice tone="warn" live`.

### `HiddenField`

`{ name: string; value: string }` — единственный способ положить скрытое значение в форму (`next`, ключ идемпотентности). Сырой `<input>` в экранах запрещён (правило 5).

```tsx
<HiddenField name="idempotencyKey" value={key} />
<HiddenField name="next" value={next} />
```

### `CodeField` и `PhoneField`

Поля на основе `TextField` (те же `label`, `name`, `error`).

| Компонент | Особенности |
|---|---|
| `CodeField` | `length?: number` (6), `defaultValue?`. Ширина под код (`max-w-code`, 10 rem), а не вся форма; подпись и ошибка у поля. Одно поле: цифровая клавиатура (`inputmode="numeric"`), `autocomplete="one-time-code"`, `maxlength` = длина × 2 (вставка «123 456» не теряет цифру), цифры одной ширины с разрядкой (`tabular-nums`, `tracking-code`). Нецифровые символы убирает схема действия: `z.string().transform(digitsOnly)` (`digitsOnly` из `@/platform/digits`), она же проверяет длину |
| `PhoneField` | `defaultValue?`. `type="tel"`, `autocomplete="tel"`, подсказка формата из `ru.app.kit.fields.phonePlaceholder` |

### `Chips`

Фильтры-ссылки без обводок: `items: { href: string; label: string; active: boolean }[]`, `label: string` (имя навигации). Обычный чип — заливка `fill`, текст `ink`, капсула; выбранный — заливка `action`, текст `on-action`, вес 600, `aria-current="true"` (в тёмной теме — светлая заливка и тёмный текст). Телефон: высота 48 px, лента выходит за поля экрана до его края (`rail-bleed`), прокручивается вбок, последний видимый чип уходит за край; выбранный при открытии прокручивается к центру ленты (`ChipsRail` — единственная клиентская часть, остальное серверное). Компьютер: высота 36 px, строки переносятся. Адреса через `to()` с параметром фильтра.

### `FilterList`

Список фильтров для левой колонки на компьютере: `title: string` (заголовок 15 px / 600 и имя `<nav>`), `items: { href; label; active }[]`. Строки-ссылки: 48 px на телефоне, 36 px на компьютере; выбранная — вес 600, галочка справа, `aria-current="true"`. Серверный.

### `Pagination`

`page`, `pageCount`, `hrefFor: (page: number) => string`, `label`. «Назад — Страница N из M — Вперёд»; при `pageCount <= 1` или нечисловых значениях ничего не рисует. Компьютер: компактная группа по центру, тихие кнопки 36 px. Телефон: кнопки 48 px делят строку. Край, где идти некуда, не показывается вовсе. Ссылки несут `rel="prev"` / `rel="next"`.

### `WorkCard`

Карточка работы: `href?` (без него карточка неинтерактивна: нет ссылки, шеврона, отклика на нажатие и кольца фокуса), `title`, `meta: string`, `byline?: string` (третья строка, текст даёт экран: «Мастер № 1042 · 48 сделок»), `priceFrom?: bigint` (тиыны, «от N ₸»), `media?: "none" | "slot"`, `photo?: { src, alt }`, `headingLevel?: 2 | 3` (по умолчанию 3; на странице-списке сразу под `<h1>` ставьте `2`).

- `media="none"` (по умолчанию): компактная текстовая карточка без области фото: заголовок 17 / 600, `meta` и `byline` 15 `muted`, цена «от» (вес 500, табличные цифры). Телефон (уплотнено, поля по вертикали 12 px): «meta · byline» одной строкой с переносом, цена в той же строке справа, шеврон 20 px. Компьютер: `meta` и `byline` отдельными строками, цена прижата к низу — карточки ряда одной высоты, цены на одной линии. `photo` в этом режиме не показывается.
- `media="slot"`: над текстом область 4 : 3 с радиусом 12 px — `photo` или ровная заглушка; шеврона нет. Нужен, когда у работ есть настоящие снимки.

Вся карточка — одна ссылка (заголовок растянут на карточку), фокус по карточке. Без `href` карточка неинтерактивна: нет ссылки, шеврона, отклика на нажатие и кольца фокуса (текст и разметка те же). Заголовок — `<h3>`; `headingLevel={2}` — для страницы-списка прямо под `<h1>`.

### `Columns`

`count: 2 | 3`, `children`. Компьютер: сетка из `count` равных колонок с зазором группы (12 px), дети растянуты по высоте; телефон: одна колонка. Для карточек одного уровня (три шага, два тарифа).

```tsx
<Columns count={3}>
  {steps.map((step) => <Card key={step.title}>…</Card>)}
</Columns>
```

### `TextLink`

`href`, `children`, `external?`. Тихая навигационная ссылка в потоке текста: `ink`, вес 500, шеврон 16 px, высота касания 48 px. Текст стоит по левой линии содержимого — без боковых отступов и отрицательных полей (для вторичного перехода вместо тихой кнопки с `-ml-6`). Наведение — подчёркивание.

`external` — файл (PDF оферты, выписка) или чужая страница в новой вкладке: обычная ссылка `<a>` без перехода и предзагрузки роутера, `target="_blank"` и `rel="noopener noreferrer"`; вместо шеврона — значок внешней ссылки, для диктора после подписи скрытый текст «(откроется в новой вкладке)» из `ru.app.kit.externalHint`. Не собирайте такую ссылку вручную на экране.

### `Rating`

`value: number | null`, `count: number`. «4,8 · 12 отзывов» текстом, без звёзд; `null` или `count` 0 — «Пока без отзывов». Корневой элемент — `span` 17 px (`ink`; «Пока без отзывов» — `muted`), поэтому встаёт значением в `ListRow` без `<p>` внутри `<span>`.

### `PhoneFrame` и `TrustCapsule` (лендинг)

`PhoneFrame`: `src`, `width`, `height`, `alt`, `sizes`, `className?` (ширина рамки). Снимок нашего экрана в рамке телефона (`phone-frame`: тёмный корпус в обеих темах, кромка, тень `float`), снимок через `next/image` с настоящими размерами (без сдвига раскладки), лениво; скругление экрана концентрично рамке (`rounded-phone-screen`). Снимки — статика `public/app-screens/` (манифест там же, временные).

`TrustCapsule`: `children`. Капсула доверия поверх фото — `glass-clear`, щит и белый текст 600, высота касания 48 px; это текст, а не кнопка. Только на фото с затемнением под ней (`scrim-photo`, `scrim-photo-top`, `scrim-hero`).

Утилиты лендинга — `src/kit/landing.css`: `bleed` (блок на всю ширину окна из колонки содержимого; страница с `[data-bleed]` обрезает горизонтальный выход за край), `hero-fold` (первый экран компьютера: `min(88vh, 860px)`, под стеклянной шапкой), `scrim-hero` (затемнение первого экрана: 30% на всём фото и 55% в колонке текста и в нижней полосе — белый ≥ 4,5:1 над белым фото, `landing.test.tsx`), `scrim-photo-top` (как `scrim-photo`, от верхнего края), `phone-frame`; токены `max-w-hero`, `max-w-lead`, `max-w-help`, `rounded-hero`, `w-hero-tile`.

### `ActionDock`

Док главного действия: внутри ровно одна главная кнопка (тип этого не проверяет — следите сами) и не более одной тихой; второстепенное действие — ссылкой вне дока (`TextLink`). На коротком экране док стоит у нижнего края над панелью вкладок, а не под содержимым. Контракт размещения: док — **последний ребёнок своей колонки**, колонка (и вся цепочка её предков до области содержимого) — обычный блок или flex-колонка без собственных `grid` / `flex-row`. Утилита `dock-column` на `main` оболочки телефона действует только при доке внутри: `main` становится flex-колонкой, а предки дока по цепочке — растянутыми колонками (`flex-grow: 1`) с нулевой специфичностью (`:where()`), поэтому раскладку, заданную классами на предках, она не перебивает; экраны без дока рендерятся как раньше. Если предок задаёт свою раскладку (`grid`, ряд), док у нижнего края на коротком экране не гарантирован — делайте колонку прямым родителем дока. `full` у кнопок внутри не ставится: ширину детей задаёт сам док (телефон — каждый на всю ширину, компьютер — по своей в ряд). Телефон: `sticky` над панелью вкладок — `bottom` = её высота (переменная `--tab-bar-height`, которую пишет `TabBar`) + зазор 8 px + отступ панели от низа; без плиты (разбор 3.4): ни стекла, ни подложки — главная кнопка висит сама с тенью `float` (`dock-float`), боковые отступы как у панели (10 px); под ней содержимое растворяется (`bar-underlay` оболочки растёт на высоту дока). Тихая кнопка рядом стоит на растворении без своей подложки — держите её только там, где под доком спокойное содержимое (образец `/v2/ui-kit/dock`). Без панели вкладок (оператор) прилипает к низу с отступом 10 px плюс безопасная зона. Компьютер: обычный блок в потоке, кнопки в ряд. Дети дока — только кнопки и ссылки напрямую (`<form>` внутри дока получит ширину вместо кнопки). Форма, которой принадлежит кнопка, стоит выше; связь — атрибутом `form`:

```tsx
<form id="request-form" onSubmit={onSubmit}>{/* поля */}</form>
<ActionDock>
  <Button type="submit" form="request-form" pending={pending}>{t.send}</Button>
</ActionDock>
```

Либо док кладётся внутрь самой формы последним ребёнком её колонки.

**Док — последний ребёнок корневой колонки экрана** (`Stack` страницы): залипание `sticky` ограничено родителем, поэтому док внутри `Card` или посреди колонки залипает только в пределах этого блока. В конце страницы он встаёт на то же место, где был прилипшим (зазор до панели 8 px, двойного отступа нет). Поведение проверено в браузере (`e2e-v2/foundation.spec.ts`, сценарии 19а–19д, страница-образец `/v2/ui-kit/dock`).

### `useActionForm` (`@/app/(app)/_shell/form`, клиентский хук)

```tsx
"use client";
const { pending, error, fieldErrors, onSubmit } = useActionForm(requestCodeAction, { onSuccess: () => setStep("code") });
<form onSubmit={onSubmit} noValidate>
  <PhoneField label={t.phone} name="phone" error={fieldErrors.phone} />
  {error && <Notice tone="danger" live>{error}</Notice>}
  <Button type="submit" pending={pending}>{t.send}</Button>
</form>
```

Форма подключается **только через `onSubmit`**, не через `<form action={…}>`: React 19 после завершения такого действия сбрасывает неуправляемые поля, и при ошибке проверки человек терял бы введённый телефон или код. `onSubmit` отменяет отправку браузера и берёт `new FormData(form)`; `submit(formData)` остаётся для программного вызова. В поля формы попадает и нажатая кнопка отправки (`name=value` через `new FormData(form, submitter)`): у нескольких кнопок («Получить код», «Отправить ещё раз») сервер различает их по значению. Образец и e2e — «Форма с действием» на `/v2/ui-kit` (сценарий 18: ошибка у поля, значение сохранено, двойной клик — один вызов).

Принимает Server Action, созданный `action()` из `@/platform/action`; действию уходят поля формы объектом (или `toInput(formData)`), повторная отправка при `pending` игнорируется. `error` — текст ответа, `fieldErrors` — первое сообщение по полю. Ответ `UNAUTHENTICATED` уводит на `to("/login")`, `CONSENT_REQUIRED` — на `to("/consent")`, оба с `?next=` текущего пути (на самом экране входа `next` не добавляется — петли нет). Чистая часть — `outcomeOf(result, here)`.

### `error.tsx`

Граница ошибок группы (app): заголовок, одна строка, «Повторить» (`retry()` Next 16) и ссылка на главную. Тексты — `ru.app.shell.error*`.

## Экраны покупателя

Добавлены задачей E2; `Stat`, `StatRow`, `Bars` и расширение `Uploader` — задачей J2 (экраны мастера). Компоненты «глупые»: только вид и доступность; данные, состояния загрузки и отправка приходят пропсами и обработчиками, вызовов модулей, server actions и `fetch` внутри нет. Серверные: `Steps`, `Timeline`, `Badge`, `MoneyPanel` (клиентский только `Explain` внутри строк). Клиентские: `Menu`, `Uploader`, `Chat`, `ChatComposer`, `SignaturePad`. Образцы — `/v2/ui-kit`.

### `Steps`

Ход сделки. Телефон — вертикальный список (подпись справа от отметки), компьютер — горизонтальная шкала (подписи под отметками); разметка одна, версию выбирают `desktop:` / `mobile:`. Семантика — `<ol>`, текущий шаг `aria-current="step"`; пройденный объявляется диктору («выполнено»).

| Проп | Тип | Смысл |
|---|---|---|
| `items` | `{ label: string; state: "done" \| "current" \| "todo" }[]` | Шаги по порядку. Текущий — вес 600 и `ink`; пройденные — галочка `accent`, подпись `muted`; будущие — пустая отметка, `muted` |
| `note` | `string?` | Пояснение к текущему шагу: на телефоне под ним, на компьютере под шкалой |
| `stopped` | `{ label: string }?` | Спор или отмена: вместо шкалы простая строка с нейтральным значком и текстом (без своей плашки: стоит в той же карточке) |

Когда использовать: «ход сделки» в карточке сделки. Когда нет: шаги мастера заявки — `WizardHeader`; доля выполненного — `Progress`. На компьютере подписи шагов 15 px и переносятся по словам: ставьте шкалу в основную колонку `Split`, а не в `Narrow`.

| Проп | Тип | Смысл |

### `Uploader` (клиентский)

Выбор и показ фото: кнопка «Добавить фото» (внутри скрытый `input type="file"` — единственное место, где сырой `input` допустим, в kit), сетка превью, счётчик «N из max». Состояния файла: загружается (полоса с ходом в процентах, без хода — пульсация), готово, ошибка (строка во всю ширину с текстом ошибки, «Повторить» и «Убрать»). На компьютере файлы можно перетащить на область. Логика загрузки (автомат `src/features/upload`) — снаружи. Подсказка о перетаскивании пропадает, когда предел достигнут. **Адреса превью (`URL.createObjectURL`) освобождает вызывающий** (`URL.revokeObjectURL` при удалении файла и при размонтировании) — kit ими не владеет; образец — `v2/ui-kit/BuyerLive.tsx`.

| Проп | Тип | Смысл |
|---|---|---|
| `items` | `{ id; name; previewUrl?; kind?: "image" \| "document"; state: "uploading" \| "done" \| "error"; progress?: number; error?: string }[]` | Файлы; `progress` — проценты 0–100; `kind: "document"` (PDF) — вместо превью значок документа и имя файла в одну строку с многоточием, полное имя — в `title` (в строке ошибки имя показано целиком), по умолчанию фото |

| `label` | `string?` | Подпись кнопки, по умолчанию «Добавить фото» (при приёме PDF задайте свою: «Добавить фото или PDF») |

### `Bars`

Столбики сумм по месяцам без библиотек графиков. По умолчанию строки «подпись — полоса — сумма» (суммы всех месяцев на виду, не наезжают друг на друга); `layout="columns"` — на компьютере вертикальные столбики с суммой над ними (нужна ширина около 90 px на столбик при суммах в миллионы; на телефоне всё равно строки). Суммы — тиыны через `Money`. Заливка — переменная `--bar` (0–100%, от самого высокого значения, ненулевое не меньше 4%) и утилиты `bar-fill` / `bar-fill-v` из `tokens.css`; цвета ролями: текущий месяц `accent` (деньги), остальные `line-strong` на дорожке `line`. Сам рисунок `aria-hidden`; для диктора — таблица-дубль (`sr-only`: подпись, столбцы «Месяц» / «Сумма», у текущего месяца пометка «текущий месяц»). Серверный.

| Проп | Тип | Смысл |
|---|---|---|
| `label` | `string` | Имя графика и подпись таблицы («Оплаты по месяцам») |
| `layout` | `"rows" \| "columns"?` | По умолчанию `rows` |
| `items` | `{ label: string; name?: string; value: bigint; current?: boolean }[]` | Столбики по порядку; `label` — «Ноя», `name` — «Ноябрь 2026» для таблицы (по умолчанию `label`); `value` — тиыны; `current` — выделенный |

Экран готовит подписи и порядок (окно из шести месяцев — `chartWindow` в `src/features/executor-finance/months.ts`); сумм в `Bars` никто не считает. `monthName`, `monthTitle`, `versusPrevious` и `GeolocationError.message` берут тексты v1 и в v2 не используются (v2: `shiftMonth`, `selectedMonth`, `chartWindow`, `error.code` и свои тексты из `ru.app`). На широком экране для столбиков задайте `layout="columns"`.

### `Chat` и `ChatComposer` (клиентские)

`Chat` — лента: свои сообщения справа на нейтральной `bubble` (светлая тема — серая, как `track`; тёмная — как `raised`: `track` там равен `surface`), чужие слева на `surface` (ставьте на серый фон страницы, не в `Card`); текст — `ink` (пары `ink`/`bubble` и `ink`/`surface` — в `contrast.test.ts`); зелёного в переписке нет; время под подложкой мелким вторичным; фото-вложения — превью-ссылки; системная строка — по центру вторичным текстом. Лента — `role="log"` (`aria-live="polite"`), перед сообщением для диктора читается автор. Прокрутка к последнему сообщению при показе и при новом, если человек был внизу или написал сам. Прокручивается **сама лента** (на компьютере окно ленты высотой 32 rem — токен `--spacing-chat`; для экрана, где чат — всё содержимое, проп `fill`: лента занимает всю высоту родителя, см. ниже): положение страницы не меняется. Лента — `relative`: скрытый автор сообщения (`sr-only`, absolute) остаётся внутри её прокрутки и не растягивает страницу на длину переписки. Прокрутка — после раскладки при показе, при новом сообщении и по росту содержимого (догрузилось фото), пока человек внизу. Для экрана, где чат — всё содержимое (телефон, лента растёт в потоке страницы), включите `pageScroll`: тогда прокручивается окно.

| Проп `Chat` | Тип | Смысл |
|---|---|---|
| `messages` | `{ id; text; time; mine?: boolean; kind?: "message" \| "system"; author?: string; attachments?: { id; url; name }[] }[]` | `time` — готовая строка |
| `composer` | `ReactNode?` | Обычно `ChatComposer`; идёт после ленты |
| `label` | `string?` | Имя ленты, по умолчанию «Переписка» |
| `pageScroll` | `boolean?` | По умолчанию `false`. `true` — прокручивается страница (чат занимает весь экран), а не лента |
| `fill` | `boolean?` | По умолчанию `false`. Компьютер: лента `flex-1 min-h-0` со своей прокруткой во всю высоту родителя (вместо окна 32 rem). Родитель — колонка `flex flex-col` на высоту окна: утилита `desktop:screen-fill` = `100dvh` − шапка (`--spacing-header`) − поля области содержимого (5 rem); заголовок экрана — `shrink-0`, поле ввода — последним. Поле ввода видно без прокрутки страницы при любой высоте окна, числе строк заголовка и размере шрифта (всё в rem). Лента не сжимается меньше 8 rem (`--spacing-chat-min`): при крупном шрифте и низком окне дальше прокручивается страница. На телефоне ничего не меняет |

Вложение: `{ id; name; url; previewUrl? }`: `url` — ссылка на полный размер, `previewUrl` — превью; без него рисуется ровная заглушка.

`ChatComposer` — многострочное поле (растёт до 5 строк), счётчик с 80% предела, кнопка отправки (значок, имя из `ru`). Не главная кнопка экрана. На телефоне — не стекло (поле ввода на стекле запрещено): сплошная полоса цвета фона от края до края (`composer-bar`, `rail-bleed`), лента над ней растворяется; полоса прилипает к низу области над панелью вкладок (как `ActionDock`, с безопасной зоной; помечена `data-action-dock`, чтобы колонка экрана растянулась на высоту); на компьютере стоит в потоке под лентой.

Шапка экрана переписки на телефоне (`PageTitle` с «Назад» и собеседником) — в обёртке с утилитой `mobile:sticky-head` (tokens.css): закреплена у верхнего края, материал — `mobile:glass-bar` рядом (стекло без линии снизу, содержимое растворяется под шапкой), выходит до краёв экрана и закрывает строку состояния; на стекле — только ink и glass-secondary (`PageTitle onGlass`, `Explain onGlass`); при открытии длинной переписки страница прокручена вниз, а шапка видна.

**Правило размещения: поле ввода — последний элемент экрана переписки, и на этом экране нет `ActionDock`.** Панель держится на `sticky` с поправкой нижнего поля, рассчитанной на конец страницы (`dock-above-bar`): всё, что стоит в потоке после неё, подтянется под панель; второй док поверх первого тоже наложится. Защиты от этого в коде нет — только правило.

| Проп `ChatComposer` | Тип | Смысл |
|---|---|---|
| `onSend` | `(text: string) => void \| boolean \| Promise<void \| boolean>` | `false` — отправка не удалась, текст остаётся; иначе поле очищается |
| `pending` | `boolean?` | Идёт отправка |
| `maxLength` | `number?` | Предел; сверх него отправка недоступна |
| `device` | `"mobile" \| "desktop"` | Enter: компьютер — отправляет, Shift+Enter — перенос; телефон — Enter всегда перенос |
| `label`, `placeholder` | `string?` | Имя поля для диктора, подсказка |
| `onAttach` | `() => void`? | Кнопка вложения; без обработчика её нет |

### `SignaturePad` (клиентский)

Холст собственноручной подписи: палец, перо, мышь (Pointer Events, `setPointerCapture`, `touch-action: none`), высота 160 px на телефоне и 192 px на компьютере, подсказка в пустом холсте, «Очистить». Штрихи хранятся отдельно и перерисовываются целиком: при смене темы (линия — `ink` текущей темы) и размера подпись не пропадает. Доступная замена — «Ввести ФИО» (текстовое поле): после переключения фокус — в поле. «Очистить» переводит фокус на холст. На движение дорисовывается только последний отрезок; полная перерисовка — при смене темы и размера. Явная смена темы (`data-theme`) подхватывается сразу, системная тема в режиме «Авто» — при возврате фокуса в окно.

| Проп | Тип | Смысл |
|---|---|---|
| `onChange` | `(value: SignatureValue \| null) => void` | `SignatureValue = string \| { typedName: string }`: рисунок — строка `data:image/png` (тёмная линия на прозрачном фоне, одинаковая в обеих темах), вводом — `{ typedName }`; пусто — `null`. Различать по `typeof value === "string"` |
| `label` | `string` | Имя области для диктора |
| `name` | `string?` | Имя поля ФИО, по умолчанию `signature-name` |
| `defaultTypedName` | `string?` | ФИО, которое стоит в поле ввода сразу (имя из профиля); при переключении на «Ввести ФИО» с непустым значением подпись отдаётся сразу — `onChange({ typedName })`. Человек может изменить |

## Окна и уведомления

Клиентские. Во всех окнах Tab ходит по кругу внутри, Esc закрывает, фокус возвращается на кнопку-открыватель, при `prefers-reduced-motion` вместо сдвигов — проявление. Шторка и диалоги модальные: затемнение под ними, нажатие на затемнение закрывает. `Popover` немодальный и без затемнения: закрывает нажатие вне него.

**Главная кнопка в открытом окне.** Правило «одно главное действие на экран» считает закрытое состояние. Открытый `ConfirmDialog` добавляет свою единственную главную кнопку (подтверждение), открытое `Explain` на телефоне — «Понятно»; это главное действие окна, а не второе на экране.

### `Sheet` (телефон)

Шторка снизу: пояснения, подтверждения, выбор из списка. Жест (тянуть, бросить вниз) даёт vaul; схватить шторку в первые 500 мс открытия нельзя. Форма iOS 26: сплошной `raised` (не стекло); неполной высоты висит в 8 px от краёв и низа со скруглением 32 px со всех сторон, дотянувшись до 11/12 окна — прилегает к краям, скругление 24 px сверху (`sheetShape`).

| Проп | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `title` | `string` | — | Заголовок (обязателен: имя окна для диктора) |
| `description` | `string?` | — | Пояснение под заголовком |
| `trigger` | `ReactElement?` | — | Кнопка-открыватель (один элемент) |
| `open`, `onOpenChange` | `boolean`, `(open) => void` | — | Управляемый режим; без `open` шторка управляется сама |
| `dismissible` | `boolean` | `true` | `false` — нельзя закрыть жестом, затемнением и Esc (пока идёт действие) |
| `onOpenAutoFocus` | `(event: Event) => void` | — | Первый фокус; по умолчанию — сама шторка, чтобы клавиатура не выезжала вместе с ней |
| `children` | `ReactNode` | — | Содержимое |

### `Dialog` (компьютер)

Диалог по центру. Те же пропсы, что у `Sheet` (`title`, `description`, `trigger`, `open`, `onOpenChange`, `dismissible`, `onOpenAutoFocus`, `returnFocusTo`, `children`), `dismissible={false}` отключает также крестик. Для подтверждений используйте `ConfirmDialog`, а не `Dialog` с самодельными кнопками.

### `ConfirmDialog`

Подтверждение действия: на телефоне шторка, на компьютере диалог. Одна главная кнопка и отказ; первый фокус — на «Отмене».

| Проп | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `device` | `"mobile" \| "desktop"` | — | Какое окно показать |
| `title` | `string` | — | Заголовок |
| `description` | `string` | — | Что произойдёт |
| `confirmLabel` | `string` | — | Глагол, называющий результат («Отменить сделку»), не «Ок» |
| `cancelLabel` | `string` | `ru.app.kit.cancel` | Подпись отказа |
| `tone` | `"primary" \| "danger"` | `"primary"` | `danger` — необратимое действие |
| `onConfirm` | `() => void \| boolean \| Promise<void \| boolean>` | — | Действие |
| `trigger`, `open`, `onOpenChange` | как у `Dialog` | — | Открытие |
| `returnFocusTo` | `RefObject<HTMLElement \| null>` | — | Куда вернуть фокус при закрытии окна без `trigger`. Подтверждение из меню: передать кнопку меню (`Menu` отдаёт её через `triggerRef`) |

Поведение `onConfirm`:

- Пока оно идёт, кнопка показывает ожидание; повторное нажатие и закрытие окна (Esc, затемнение, жест, «Отмена») не срабатывают. Двойной клик не даёт двойного эффекта.
- Вернуло ничего или `true` — окно закрывается.
- Вернуло `false` — окно **остаётся открытым**. Так отвечают, когда сервер отказал.
- Бросило исключение или промис отклонён — окно остаётся открытым, ошибка пишется в лог (`logger.warn`) и дальше не идёт.
- **Показать ошибку пользователю обязан сам `onConfirm`** — тостом `toast.error(t.text)`. Окно текста ошибки не знает.

```tsx
<ConfirmDialog
  device={device}
  tone="danger"
  trigger={<Button variant="danger">{t.cancelDeal}</Button>}
  title={t.cancelTitle}
  description={t.cancelBody}
  confirmLabel={t.cancelConfirm}
  onConfirm={async () => {
    const ok = await cancelDeal(deal.id, idempotencyKey);
    if (!ok) toast.error(t.cancelFailed);
    return ok;
  }}
/>
```

### `Popover` (компьютер)

Поповер у кнопки: пояснение, короткий выбор. Немодальный: страница за ним прокручивается, нажатие вне закрывает и сразу срабатывает там, куда нажали. Растёт из кнопки (масштаб 0,96 → 1, пружина без отскока).

| Проп | Тип | Смысл |
|---|---|---|
| `trigger` | `ReactElement` | Кнопка-открыватель (обязательна) |
| `title` **или** `label` | `string` | Имя для диктора: видимый заголовок или, без заголовка, `aria-label`. Один из двух |
| `open`, `onOpenChange` | `boolean`, `(open) => void` | Управляемый режим |
| `material` | `"solid" \| "glass"` | `solid` (по умолчанию) — сплошной `raised` с тенью `overlay`, для текста пояснений (длинный текст на стекле запрещён); `glass` — `glass-thick`, для короткого выбора |
| `children` | `ReactNode` | Содержимое (ширина 20 rem) |

### `Toaster` и `toast`

`toast("Сохранено")`, `toast.error(...)`, `toast.loading(...)` — тосты (sonner). `toast` вызывается из обработчиков клиентских компонентов. `Toaster` ставит **оболочка**, один на всё приложение (`device`: телефон — сверху по центру, компьютер — снизу справа); в экранах его не монтируют. Материал тоста (`TOAST_MATERIAL`): компьютер — `glass-thick`; телефон — сплошной `raised` с тенью `overlay` (сверху тост лёг бы на стекло шапки переписки и круглых кнопок — стекло на стекле). Вторичный текст — `glass-secondary`.

```tsx
<Button variant="secondary" onClick={() => toast(t.saved)}>
  {t.save}
</Button>
```

## Тема

### `Segmented`

Сегментированный переключатель: равные сегменты в одну строку, выбранный — `aria-pressed`. Сегменты — кнопки отправки одной формы, **форму даёт вызывающий**; у каждого своё действие сервера (`formAction`). Форма серверная, но без JavaScript отправка сейчас отклоняется из-за заголовка `Referrer-Policy: no-referrer` (решение владельца, см. спеку, раздел 14).

| Проп | Тип | Смысл |
|---|---|---|
| `legend` | `string` | Подпись группы |
| `options` | `{ value: string; label: string; formAction }[]` | Сегменты; подписи короткие |
| `value` | `string` | Выбранное значение |

### `ThemeSwitch`

Не часть kit: лежит в оболочке (`apps/web/src/app/(app)/_shell/ThemeSwitch.tsx`) и собран из `Segmented`: «Авто / Светлая / Тёмная», кука `theme`; действие формы — `chooseTheme` (обёртка над `setTheme`, которое идёт через `action()`: неверное значение — результат с ошибкой, а не 500). Без JavaScript — та же оговорка, что у `Segmented`. Ставят в настройках и на витрине, свой не пишут. Для выбора темы в коде есть `getTheme()` и `parseTheme()` (`@/kit/theme`, тип `Theme = "system" | "light" | "dark"`).

## Вспомогательное

- `cn(...)` — склейка классов (для `className` у `Card`, `Stack`, `Button`).
- `pressable` — утилита отклика на нажатие (tokens.css): масштаб 0,97 за 100 мс, у отключённого — нет, при `prefers-reduced-motion` — без масштаба. Кнопки kit её уже несут.
- `SPRING` — параметры пружины без отскока для собственного движения (анимировать только `transform` и `opacity`).
- `formatMoney`, `buttonClasses` — см. выше.

## Чего в kit нет и как поступать

Нет, в частности: таблиц, вкладок внутри экрана, календаря и выбора даты, загрузки файлов, карусели и галереи, баннера-предупреждения, выпадающего меню действий, поля телефона и суммы с маской, пагинации и «ещё»-списков, аватара.

Если нужного нет:

1. Сначала проверьте, не решается ли это сочетанием имеющегося (`Card` + `List` + `StatusChip` закрывают большинство списков и сводок).
2. Если не решается, **попросите новый компонент kit** (владельцу дизайн-системы) — с описанием, где он нужен и по какому эталону из `reference/`. Не собирайте его вручную в экране: сторожа запретят сырые `<button>`/`<input>`, произвольные значения и цвета, а разные самодельные версии разойдутся по виду и доступности.
3. Новый компонент появляется в `src/kit/` с тестом, образцом на `/v2/ui-kit` и строкой в этом справочнике; до этого экран ждёт или показывает ближайшее готовое.
4. Тексты компонентов kit берутся из `ru.app.kit`, не из экрана; компонент не знает ни слов предметной области, ни адресов.
