# operator-engineer
## Задача
Все экраны `/operator/**` — только роль OPERATOR (`requireUser("OPERATOR")` в каждом действии и на каждой странице).
1. **Очередь регистраций**: PENDING-исполнители (ИИН/БИН — последние 4 цифры), подтвердить с сегментом / отклонить с причиной (через `identity.reviewExecutorRegistration`, пока нет — адаптер `// INTEGRATOR:`); уведомление; аудит.
2. **Ручное добавление исполнителя** (телефон, форма, наименование, ИИН/БИН — шифрование, сегмент) → APPROVED, `addedByOperator`.
3. **Сегменты**: смена с причиной (аудит до/после).
4. **Справочник `FurnitureType`**: добавить, переименовать, скрыть, порядок.
5. **Заявки без откликов** дольше N часов (по умолчанию 24).
6. **Споры**: очередь, карточка (позиции сторон, вложения, этап, история сделки), решение по структуре схемы → `deal-core.resolveDispute` (пока нет — адаптер).
7. **Журнал аудита** с фильтрами (сущность, scope, действие, актор, период), постранично по `seq`.
8. **Отчёт и сверка**: сделки по статусам, этапы, оплаты (DUE/MARKED_PAID/CONFIRMED), расхождения (MARKED_PAID дольше N дней без подтверждения); эскроу-сделки — `payments.reconcile` (пока нет — адаптер). Выгрузка CSV.
9. **Только DEMO_MODE**: «Сбросить демо» (TRUNCATE + сид из `src/demo/seed.ts`, подтверждение в модалке) и переключатель режима оплаты для новых сделок (`PlatformSetting["payments.rail"]`: manual / escrow-simulator).
10. **Показ банку** `/bank-demo` (только DEMO_MODE): сценарий по шагам полного цикла (заявка → отклики → замер → договор с хэшем и подписями → пополнение эскроу в симуляторе → этапы с траншами → закрытие) со ссылками на экраны под нужной персоной, журналом сделки (`scopeHistory`), документами с хэшами и выпиской `escrow-simulator`. Честная пометка «Симулятор банка».
11. **Тесты**: доступ только оператору (каждое действие), модерация, ручное добавление, смена сегмента с аудитом, сброс демо запрещён при DEMO_MODE=false.
