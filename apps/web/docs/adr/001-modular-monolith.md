# ADR-001. Модульный монолит с границами в ESLint

**Статус:** принято (фаза A).

## Контекст
MVP держал всю логику в `src/lib/deal/service.ts` и экранах. Нужно параллельно развивать 8 модулей разными агентами и показать банку понятную архитектуру, сохранив один деплой на Vercel.

## Решение
- Один Next.js-проект; модули в `src/modules/<имя>/` с единственной публичной точкой `index.ts` (и `client.ts` для клиентских компонентов, без `server-only`).
- ESLint `no-restricted-imports` запрещает импорт внутренностей чужого модуля и импорт `src/app` из модулей; `deal-core` дополнительно не видит `src/verticals`.
- Общие файлы (`prisma/schema.prisma`, `package.json`, `src/platform/`, `src/ui/`, `src/jobs.ts`, `src/i18n/ru.ts`) меняет только ведущий инженер. Тексты разбиты по зонам `src/i18n/ru/<зона>.ts`, у каждой зоны один владелец.
- Межмодульные вызовы — функции из `index.ts`. Транзакцию между модулями передаём параметром `tx: Db`.
- Фоновые задачи: модуль экспортирует `jobHandlers` с ключами `<модуль>.<задача>`; `src/jobs.ts` собирает их.

## Последствия
- Модуль можно вынести в сервис, не трогая остальных.
- Нарушение границ ловит `npm run lint` в CI.
