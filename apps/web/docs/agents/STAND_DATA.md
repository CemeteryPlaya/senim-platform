# Данные стенда (сид, ТЗ MVP v1.0)

`npm run db:reset` или `APP_ENV=dev npx prisma db seed` (непустую базу пересоздаёт только при явном `APP_ENV` dev или staging, при prod сид не пишет ничего — `src/seed/plan.ts`). Код — `src/seed/`: описание — `data.ts`, «до сделок» — `seed.ts`, сделки — `deals.ts`. Пересев — `reseedStand(db)`: `ResetStand` в identity (сессии, лимиты, идемпотентность всех людей стенда) и TRUNCATE всех таблиц web — после пересева все выходят. Сброса из интерфейса нет. Телефоны — +7 700 000 XX XX, ИИН/БИН — тестовые с верной контрольной суммой, IBAN выплат — `KZ..000DEMO…` (верный mod-97, банка с кодом 000 нет; пометка в номере счёта, на экране — только последние 4 цифры).

Сид — в два шага:
1. **До сделок** (одна транзакция, даты «N дней назад»): справочник и цены материалов, люди, мастера (портфолио, KYC с тестовыми PDF «ТЕСТОВЫЙ ДОКУМЕНТ»), заявки, отклики и торг (раунды `PriceProposal`), сценарии до договора, уведомления регистрации и откликов.
2. **Сделки** — настоящими сервисами, от имени тех, кто нажимает кнопку: `requests.acceptPrice` → `deal-core.createDeal` (оферта — PDF documents), подписи documents (собственноручно — напечатанное имя, ЭЦП — mock), `payForDeal`, `startWork`, `addProgressReport`, `submitReady` (фото JPEG через files, GPS у адреса или в ~2 км), подпись акта, `cancelDeal`, `openDispute`/`resolveDispute`; на manual — оператор подтверждает операции номером `ТЕСТ-NNNN`, датой и тестовым сканом (PDF «ТЕСТОВЫЙ ДОКУМЕНТ — не настоящий»). Сервисы пишут «сейчас», затем `retime.ts` одной транзакцией переносит записи каждого действия на день из плана (`DealPlan.at`: оплата, начало работ, отчёты, сдача — по дням; `thisMonth` — внутри текущего месяца), заменяет номера операций тестового провайдера `MOCK-…` на 12-значные номера банка и пишет отзывы (`REVIEWS`). Для этого он на время своей транзакции отключает триггеры только-добавления журнала аудита и журнала денег (нужен владелец таблиц). PDF оферты и акта хранят дату засева. Сделки на провайдере `mock` — тестовые деньги: операции журнала `isTest` (видит только оператор; признака сделки `isDemo` больше нет), суммы — `computeDealMoney`, журнал — единственный источник денег. Порты (`src/ports.ts`) сид регистрирует сам.

## Прочее

- «Вдохновение» и портфолио: 20 работ портфолио, 6 — в «Подборке Сенім» (флаг `inspiration` выключен — раздела нет в меню). Портфолио из сделок (флаг `dealPortfolio`) в сиде нет.
- Ссылки в уведомлениях сида: `/requests/:id`, `/executor/requests/:id`, `/operator/executors/:id`; уведомления сделок и денег (`deal.offer.ready`, `deal.signed`, `deal.ready`, `money.*`, `dispute.*`) пишут сервисы.
- Сид и `npm run jobs` запускаются через `tsx --import ./scripts/server-only-hook.mjs` (пакет `server-only` подменяется пустым модулем, как в тестах). Файлы (фото, PDF, сканы) — в хранилище `STORAGE_PROVIDER` (по умолчанию `./storage`).
- **Место на диске.** Файлы (`STORAGE_PROVIDER=local`) лежат в `STORAGE_LOCAL_DIR`: у dev (`npm run dev`) — `apps/web/storage`, у e2e и стенда — `apps/web/storage-e2e` (задаёт `e2e/web-server.ts` для сервера, global-setup и `reseed()`). Папка принадлежит одной базе: в её корне метка `.senim-storage-db` с именем базы. Метку пишет сид стенда (`prisma db seed`, явный `APP_ENV` dev или staging) и только в новую или пустую папку; `storage:prune` её не создаёт. Пересев после TRUNCATE удаляет из папки файлы, на которые не ссылается `StoredFile` (`storageKey`, `previewKey`) и которые старше часа (загрузка без записи живёт час), — только если метка совпадает с базой `DATABASE_URL` (`src/modules/files/prune.ts`); нет метки или она чужая — чистка пропускается с предупреждением, сбой чистки пересев не роняет; при prod — никогда. Вручную: `APP_ENV=dev DATABASE_URL=<база стенда> STORAGE_LOCAL_DIR=<её папка> npm run storage:prune` (при prod, без `APP_ENV`, без метки и при чужой метке — отказ). Интеграционные тесты пишут файлы во временную папку прогона `<tmp>/senim-test-storage-*` (`test/storage-dir.ts`), удаляемую в конце прогона; папки прерванных прогонов старше суток удаляет следующий прогон. Кэш Turbopack: `experimental.turbopackGc` (next.config.ts) чистит его сам; перед стартом e2e-сервера `next dev` кэш `.next-e2e/dev/cache/turbopack` больше 5 ГБ удаляется целиком (`e2e/turbopack-cache.ts`).
- Тесты сида: `src/seed/seed.int.test.ts` (сделки во всех статусах, журнал сходится с формулами, manual, споры, GPS, KYC, время по дням, номера операций, отзывы), `src/seed/timeline.test.ts` (план времени), `src/seed/plan.test.ts` (когда сид пишет), `requests/seed-compat.int.test.ts`. Хранилище в тестах — временная папка (`useSeedStorage`).
