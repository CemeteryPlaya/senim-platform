# План демо-MVP: платформа безопасных сделок для мебельщиков (Казахстан)

> Цель: к встрече поднять на Vercel **кликабельный прототип с живой логикой**: сделка проходит все статусы, а подпись ЭЦП и банк пока замоканы.
> Основатели не технари, поэтому показываем **путь пользователя**, а не архитектуру. Технические детали держим в запасе на случай вопросов.

## 2. Стек (совпадает с вакансией, чтобы заодно показать компетенцию)

| Слой | Выбор | Почему |
|------|-------|--------|
| Фреймворк | **Next.js (App Router) + TypeScript** | Фронт и бэк в одном проекте, деплой на Vercel без настройки |
| UI | **Tailwind CSS + shadcn/ui** | Быстро выглядит прилично, адаптивно под телефон |
| БД | **PostgreSQL (Neon через Vercel Marketplace) + Prisma** | Требование вакансии; состояние сделки сохраняется между вкладками и устройствами |
| Файлы | Vercel Blob (или статичные фото в демо) | Портфолио, фото сдачи работы |
| «Приложение» | **PWA** (manifest + установка на телефон) | На встрече можно показать «приложение» на телефоне без App Store. Нативное приложение (Expo) — следующий этап |
| Авторизация в демо | **Переключатель ролей** («Войти как Заказчик / Мастер / Админ») | Без возни с SMS; реальная авторизация — в MVP |

### Интеграции в демо замоканы, но за интерфейсами (адаптерами)

```
lib/providers/
  signature/   SignatureProvider   → MockNcaLayer   (потом: NCALayer + NCANode / SIGEX)
  escrow/      EscrowProvider      → MockBank       (потом: API банка-партнёра)
  payout/      PayoutProvider      → MockPayout
  kyc/         SelfEmployedCheck   → Mock           (потом: проверка статуса по ИИН)
```

Это сильный аргумент на встрече: **«реальные интеграции подключаются заменой одного модуля, остальной продукт уже работает»**.

## 3. Модель данных (Prisma, минимум)

- **User**: id, role (CLIENT | MASTER | ADMIN), name, phone, iin, city
- **MasterProfile**: userId, type (SELF_EMPLOYED | IP | TOO), specialties[], rating, verified, portfolio[]
- **Deal**: id, clientId, masterId, title, description, specs (json: размеры, материалы), amount, commissionRate (0.06), commissionAmount, payoutAmount, deadline, status, autoAcceptAt
- **DealEvent**: dealId, type, actorId, payload, createdAt. Это таймлайн и журнал аудита (для финтеха обязателен)
- **Signature**: dealId, userId, certSubject, iin, signedAt, signatureData (mock CMS)
- **EscrowAccount**: dealId, bankRef, status (OPENED | FUNDED | RELEASED | REFUNDED), amount
- **Dispute**: dealId, openedBy, reason, resolution (RELEASE | REFUND | PARTIAL), resolvedBy
- **Message**: чат внутри сделки (опционально в демо)

## 4. Статусная машина сделки (ядро продукта)

```
DRAFT ──► OFFER_SENT ──► AGREED ──► SIGNING ──► SIGNED ──► AWAITING_FUNDING ──► FUNDED
              │             ▲                                                     │
              └─ CHANGES ───┘                                                     ▼
                REQUESTED                                                   IN_PROGRESS
                                                                                  │
                                                                                  ▼
             RELEASED ◄── ACCEPTED ◄── (подтверждение / автоприёмка) ◄──── DELIVERED
                ▲                                                                 │
                └──── DISPUTE_RESOLVED (release / refund / partial) ◄── DISPUTE ◄─┘

CANCELLED: возможен до FUNDED. После FUNDED отмена идёт только через спор или возврат (REFUNDED).
```

- Переходы описаны в одном модуле (`lib/deal/state-machine.ts`) с проверкой роли: кто какой переход может сделать.
- Каждый переход пишет `DealEvent`. Отсюда таймлайн в UI и аудит.
- На странице сделки кнопки зависят от статуса и роли. Именно это основатели «щупают» руками.

## 6. Что обсудить на встрече (вопросы к основателям)

Эти вопросы стоит задать: от ответов зависит архитектура и сроки настоящего MVP.

### Деньги и банк
1. **Какой банк-партнёр** по эскроу и есть ли у него API? (Halyk, Freedom, Jusan, Bereke, Kaspi?) Эскроу в РК банки чаще всего предлагают для долевого строительства. Есть ли договорённость о продукте под сделки физлиц, или нужна другая схема: номинальный счёт, агентская схема через платёжного провайдера (Halyk ePay, Freedom Pay, CloudPayments KZ)?
2. **Предоплата на материалы.** Мебельщики обычно берут 50–70% аванса на ЛДСП, фурнитуру и фасады. Если всё заморожено до конца, мастерам будет невыгодно. Предложение: **этапы сделки** (например, «материалы закуплены», «готово»), частичное раскрытие по этапам.
3. **Кто платит комиссию банка** за эскроу и эквайринг: из 6%, сверху или заказчик?
4. 6% считаются от всей суммы или от суммы без материалов? Есть ли минимальная комиссия?

### Юридическое
5. **Подпись ЭЦП заказчиком-физлицом.** У многих клиентов нет ЭЦП на компьютере. Удобнее всего подписание через **eGov Mobile по QR** (например, через сервис SIGEX), NCALayer оставить как альтернативу. Согласны?
6. **Шаблон договора** (бытовой подряд): кто готовит, юрист есть?
7. **Споры.** Кто разбирает спор: оператор, независимый эксперт, суд? Какие сроки? Что с автоприёмкой, если заказчик молчит?
8. **Самозанятые.** Как проверяем статус (по ИИН через налоговую)? Работаем ли с ИП и ТОО (мебельные компании) с первого дня?
9. Нужна ли платформе **лицензия/регистрация платёжной организации** в Нацбанке, если деньги идут только через счёт банка? Нужен ответ юриста. От этого зависит схема.

### Продукт
10. Что первично: **веб или мобильное приложение**? Предложение: веб плюс PWA сейчас, нативное приложение (React Native/Expo) после проверки спроса.
11. Каталог мастеров или только «приведи своего мастера» (сделка по ссылке)? Второй вариант проще запустить: мастера сами приводят клиентов, чтобы получить гарантию оплаты.
12. Нужны ли отзывы и рейтинги, чат, замерщик, 3D/чертежи в сделке?
13. Какие города на старте?

### Инфраструктура (важно сказать заранее)
14. **Персональные данные граждан РК (ИИН и т. д.) по закону должны храниться на серверах в Казахстане.** Vercel подходит для демо, но продакшен с реальными данными нужно размещать в казахстанском облаке (PS Cloud, QazCloud и т. п.). Банки тоже это спросят.

### Сотрудничество
15. Формат работы, занятость, оплата, права на код, роадмап и бюджет Astana Hub.
