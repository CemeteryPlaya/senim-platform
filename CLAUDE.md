# Сенім — правила работы с кодом

1. **Перед любой работой с кодом прочитай `./SKILL.md` и следуй ему** (он же — скилл `project-standards`).
2. Прочитай `AGENTS.md`: Next.js 16 отличается от того, что ты знаешь. Перед работой с роутингом, Server Actions, кэшем и proxy (бывший middleware) смотри `node_modules/next/dist/docs/`.
3. Prisma 7: скиллы `prisma-cli`, `prisma-client-api`, `prisma-orm-setup` в `.claude/skills/`. Клиент генерируется в `src/generated/prisma`, импорт — `@/generated/prisma/client` и `@/generated/prisma/enums`.
4. Полное задание — `docs/AGENT_PROMPT.md`; прогресс — `docs/PROGRESS.md`; термины — `docs/GLOSSARY.md`; решения — `docs/adr/`.

## Архитектура: модульный монолит

```
src/app/              маршруты и экраны, без бизнес-логики
src/modules/<имя>/    модуль; снаружи — только index.ts (и client.ts для клиентских компонентов)
src/verticals/furniture/  всё мебельное: типы, стили, шаблоны этапов, правила сегмента
src/platform/         db, env (zod), errors, logger, crypto, jobs, rate-limit, action
src/ui/               дизайн-токены и базовые компоненты
src/i18n/ru.ts        все тексты; каждая зона — свой файл в src/i18n/ru/
src/jobs.ts           сборка обработчиков фоновых задач из модулей
```

- Импорт из другого модуля — только `@/modules/<имя>` (ESLint `no-restricted-imports`). Внутри модуля — относительные пути.
- `deal-core` не знает про мебель и не импортирует `verticals/`: шаблоны этапов получает параметром.
- Модули не импортируют `src/app/`.

## Definition of Done

- `npm run typecheck`, `npm run lint`, `npm test` — без ошибок. Без `any`; `@ts-expect-error` только с описанием.
- Каждый вход на сервер (Server Action, route handler) — zod-схема (`action()` из `@/platform/action`), затем `requireUser(...роли)` из `@/modules/identity` первой строкой обработчика.
- Изменение состояния сделки или заявки — через сервис модуля в `transaction()` с `recordAudit()` в той же транзакции.
- Конкурентные переходы — `updateMany({ where: { id, status: <ожидаемый> } })` + `expectOneUpdated()`, либо `SELECT … FOR UPDATE`. Двойной клик не должен дать двойного эффекта.
- Статусная машина — таблица переходов в коде (`from`, `to`, кто, условия); тест на каждый разрешённый и каждый запрещённый переход на реальной тестовой БД (`*.int.test.ts`).
- Тексты интерфейса — только русские, только из `ru` (`src/i18n/ru.ts`), не в разметке.
- Доступность: основной текст ≥ 17–18 px, контраст вторичного текста ≥ 4,5:1, кнопки и поля ≥ 48 px, одно главное действие на экране, «Назад» всегда видна, работает с клавиатуры и при увеличенном шрифте, мобильный экран — основной.
- Никаких `console.log` — только `logger` из `@/platform/logger`.
- Коммит маленький, в формате Conventional Commits, тело: почему, что, как проверено.

## Продуктовые инварианты (не менять; ТЗ MVP v1.0, ADR-009)

- Деньги клиентов никогда не проходят через счета ТОО — ни в коде, ни в текстах, ни в схемах в `docs/`. Деньги лежат в банке; платформа только фиксирует операции.
- Модель денег (ТЗ п. 6): цена по оферте X; покупатель платит X + защита 2% (вверх до тиына); мастер получает X − гарантия 4% (вниз до тиына); доход платформы = оплачено − выплата. Одна функция — `computeDealMoney` в `@/modules/payments`. Суммы сделки — тиыны (`BigInt`), никакого float.
- Одна оплата покупателя в начале (PAID_HOLD), одна выплата мастеру в конце (ACCEPTED → SPLIT_PAYOUT). Авансов и оплат по этапам нет.
- Статусы ТЗ п. 9: `CREATED → PAID_HOLD → IN_PROGRESS → READY → ACCEPTED → SPLIT_PAYOUT`, конечные `CANCELLED`, `REFUNDED`; перескоки запрещены кодом. Открытый спор блокирует выплату.
- Журнал денег (`MoneyTransaction`) — единственный источник правды о деньгах: блок денег и история денег строятся из него, а не из статуса сделки.
- В интерфейсе покупателя и мастера нет слов «комиссия» и «эскроу» (тест). Покупатель — «Защита сделки (2%)», мастер — «Гарантия оплаты и клиента (4%)»; вместо «эскроу» — «деньги в банке под защитой». «Эскроу» — только в оферте, договорах, `docs/` и у оператора.
- Контакты (телефон, Instagram) обеих сторон скрыты до заключения оферты (`Deal.signedAt`); после — видны обеим сторонам сделки. До оферты в чате маскируются телефоны, ссылки на мессенджеры и e-mail. Режим показа имени исполнителя (ADR-006) — по-прежнему у оператора. ИИН/БИН раскрываются только в договоре.
- Название продукта — только из `src/config/brand.ts` (тест).
- Возможности вне Фазы 1 — за флагами `src/platform/features.ts`, по умолчанию выключены; не удаляются.
- ИИН/БИН и IBAN в БД только зашифрованы (`encryptPii`), в интерфейсе — последние 4 символа.
- Демо-персоны, «Сбросить демо» и страница показа банку — только при `DEMO_MODE=true`; демо-сделки помечены «тестовые». `APP_ENV=prod` запрещает `DEMO_MODE`, моки SMS, подписи и платежей, провайдер `freedompay`.
- Внешние сервисы — за интерфейсами с моком; выбор через env, проверенный в `src/platform/env.ts`. API внешних сервисов не выдумываем: нет документации — только интерфейс и TODO.

## Команды

```bash
npm run db:up        # Postgres в Docker на порту 5442 (базы senim, senim_test, senim_e2e)
npm run db:reset     # миграции с нуля + демо-данные
npm run dev          # http://localhost:3100
npm run check        # typecheck + lint + test
npm run test:e2e     # Playwright
npm run jobs         # фоновые задачи локально (-- --watch — в цикле)
```

Тестам нужны `TEST_DATABASE_URL` и `E2E_DATABASE_URL` (см. `.env.example`).
