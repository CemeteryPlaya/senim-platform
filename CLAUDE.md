# Сенім v2 — правила работы с кодом

Репозиторий v2: Go-микросервисы + `apps/web` (Next.js 16, импортирован с историей из `mvp-scale-arna@main` через `git subtree`).

1. Спека: `docs/superpowers/specs/2026-11-08-platform-v2-architecture-design.md`; планы — `docs/superpowers/plans/`; решения — `docs/adr/` (ADR-010 — микросервисы и gRPC); правовые материалы — `docs/legal/`.
2. Работа внутри `apps/web` — по `apps/web/CLAUDE.md`, `apps/web/SKILL.md` и `apps/web/AGENTS.md` (Next.js 16 отличается от того, что ты знаешь: `apps/web/node_modules/next/dist/docs/`).
3. Подтягивать обновления демо: `git subtree pull --prefix=apps/web D:/mvp-scale-arna main` — часто и небольшими порциями.

## Архитектура (спека, раздел 4)

```
Браузер → edge (Envoy) → web (Next.js, BFF) → mesh-gateway (Envoy, gRPC, mTLS)
  → identity | deal | marketplace | operator | documents | files | notify | audit
  → PostgreSQL (своя база и роли у каждого сервиса), NATS JetStream, S3 (MinIO), OTel → Grafana
```

```
pkg/                       инфраструктурные пакеты (config, logging, outbox/inbox, authz, ...)
services/<имя>/            Go-сервис; своя база, свои миграции, свои роли
gen/go/                    сгенерированный код (buf); руками не править
proto/senim/<сервис>/v1/   контракты; события — proto/senim/events/v1
apps/web/                  текущий Next.js
deploy/compose/            docker compose, профили core и full
```

- Синхронно — gRPC (connect-go v2, протокол gRPC поверх HTTP/2) через mesh-gateway; асинхронно — события NATS JetStream.
- **Сервис-владелец сам проверяет права**: подпись внутреннего токена (Ed25519, JWKS `identity`), роль и владение объектом. `web` и `operator` не заменяют эту проверку.
- **Изменяющий метод принимает `idempotency_key`**; сервис хранит ключ и результат, повтор даёт тот же результат. Envoy ретраит только идемпотентные методы: неидемпотентный метод не ретраится — для пакета сервиса в `mesh.yaml` повтор только на `unavailable,connect-failure,refused-stream`, без `reset`.
- **Событие пишется в `outbox` в той же транзакции**, что и изменение данных; получатель пишет `event_id` в `inbox` и обрабатывает один раз. Аудит — тоже событие в outbox.
- Ни одного вызова без дедлайна; дедлайн по умолчанию в `web` — 5 с, дальше передаётся.
- Сервисы возвращают коды ошибок, не тексты: деталь — `senim.common.v1.ErrorDetail`. Тексты — только русские, только в `apps/web` (`ru`).
- `operator` — оркестратор: изменения чужих данных только вызовом сервиса-владельца.
- `deal` не знает про мебель, заявки и тексты.

## Definition of Done

- Go: `go vet`, `go tool golangci-lint run ./...`, `go tool buf lint`, `go test ./...` — без ошибок. Web: `npm --prefix apps/web run typecheck`, `lint`, `test` — без ошибок. Без `any` (TS); `@ts-expect-error` только с описанием.
- Каждый вход на сервер — валидация схемой (protobuf/zod), затем проверка токена и прав первой строкой обработчика.
- Изменение состояния сделки или заявки — в транзакции, с событием аудита в outbox в той же транзакции.
- Конкурентные переходы — условный `UPDATE ... WHERE id = $1 AND status = <ожидаемый>` с проверкой числа строк, либо `SELECT ... FOR UPDATE`. Двойной клик или повтор не должны дать двойного эффекта.
- Статусная машина — таблица переходов в коде (`from`, `to`, кто, условия); тест на каждый разрешённый и каждый запрещённый переход на реальной БД.
- Деньги — тиыны, целые числа (`int64` / `BigInt`), никакого float.
- Тексты интерфейса — только русские, только из `ru`, не в разметке.
- Доступность: основной текст ≥ 17–18 px, контраст вторичного текста ≥ 4,5:1, кнопки и поля ≥ 48 px, одно главное действие на экране, «Назад» всегда видна, работает с клавиатуры и при увеличенном шрифте, мобильный экран — основной.
- Никаких `console.log` и `fmt.Println` в рабочем коде — только логгер (`logger` в web, `log/slog` в Go).
- Коммит маленький, Conventional Commits, тело: почему / что / как проверено.

## Продуктовые инварианты (не менять; ТЗ MVP v1.0, ADR-009)

- Деньги клиентов никогда не проходят через счета ТОО — ни в коде, ни в текстах, ни в схемах в `docs/`. Деньги лежат в банке; платформа только фиксирует операции.
- Модель денег (ТЗ п. 6): цена по оферте X; покупатель платит X + защита 2% (вверх до тиына); мастер получает X − гарантия 4% (вниз до тиына); доход платформы = оплачено − выплата. Одна функция — `ComputeDealMoney` в `deal`. Суммы — тиыны.
- Одна оплата покупателя в начале (PAID_HOLD), одна выплата мастеру в конце (ACCEPTED → SPLIT_PAYOUT). Авансов и оплат по этапам нет.
- Статусы ТЗ п. 9: `CREATED → PAID_HOLD → IN_PROGRESS → READY → ACCEPTED → SPLIT_PAYOUT`, конечные `CANCELLED`, `REFUNDED`; перескоки запрещены кодом. Открытый спор блокирует выплату.
- Журнал денег (`MoneyTransaction`) — единственный источник правды о деньгах: блок денег и история денег строятся из него, а не из статуса сделки.
- В интерфейсе покупателя и мастера нет слов «комиссия» и «эскроу» (тест). Покупатель — «Защита сделки (2%)», мастер — «Гарантия оплаты и клиента (4%)»; вместо «эскроу» — «деньги в банке под защитой». «Эскроу» — только в оферте, договорах, `docs/` и у оператора.
- Контакты (телефон, Instagram) обеих сторон скрыты до заключения оферты; после — видны обеим сторонам сделки. До оферты в чате маскируются телефоны, ссылки на мессенджеры и e-mail. ИИН/БИН раскрываются только в договоре.
- Название продукта — только из `apps/web/src/config/brand.ts` (тест).
- Возможности вне Фазы 1 — за флагами, по умолчанию выключены; не удаляются.
- ИИН/БИН и IBAN в БД только зашифрованы (envelope-шифрование с `kid`), в интерфейсе — последние 4 символа.
- Демо-персоны, «Сбросить демо» и страница показа банку — только при `DEMO_MODE=true`. `APP_ENV=prod` запрещает `DEMO_MODE`, моки SMS, подписи и платежей: слабый, пустой или повторяющийся секрет, мок или `DEMO_MODE` — сервис не стартует и называет переменную.
- Внешние сервисы — за интерфейсами с моком; выбор через конфиг, проверенный при старте. API внешних сервисов не выдумываем: нет документации — только интерфейс и TODO.

## Порты и память

- Порты хоста (только 127.0.0.1): edge `8180`, Postgres v2 `5452`, NATS `4222`, mesh `9443` (для дымового теста mTLS), Grafana `3300` (профиль full), MinIO `9100`/`9101` (профиль `storage`, не входит в core: образ `minio/minio` больше не скачивается, S3-совместимый образ выбирает план 4). OTLP `4317` наружу не публикуется. Не занимать `3000`, `3100`, `5440`, `5442`.
- Бюджет памяти: профиль compose `core` ≤ 3 ГБ, `full` ≤ 6 ГБ, Go-сервис в простое ≤ 64 МБ.

## Окружение агента

- Хуки запрещают любые пути и команды, содержащие подстроку «точка + env». Файлы переменных в этом репозитории называются `*.vars` (локальные — `*.vars.local`, в git не попадают; примеры — `*.vars.example`). Переменные передавай в командной строке.
- Все файлы с LF (`.gitattributes`).
- Go вне PATH на Windows: `export PATH="/c/Program Files/Go/bin:$HOME/go/bin:$PATH"`. Инструменты — `go tool buf|sqlc|goose|golangci-lint|govulncheck`. Тесты локально без `-race` (нет gcc); `-race` — в CI.
- Не делай `git push`, не создавай удалённые репозитории, деплой и регистрацию сервисов.
